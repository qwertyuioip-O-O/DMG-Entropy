# DMT13: 새 자료에서 구조를 덜어 내는 실험

2026-10-22. **기본값은 234, 압축 우선 선택지는 250을 유지한다.**
전문가 혼합을 제거한 후보 251/mask95는 연구용으로만 남겼다.
이번 환경에서 속도는 개선됐지만 압축률을 일관되게 개선했다는 근거는 부족하다.

## 새로운 검증 자료

Lichess 공개 대회 8개에서 서로 다른 기보 1,049판, 72,443수,
648명의 표준 체스 기보를 확보했다. 1/3/5/10분 계열이며 온라인 속기 중심이다.
기존 묶음과 같은 전체 UCI 수열 및 새 자료 내부 중복은 제거했다.
합법적 표준 초기 배치, 정상 파싱, 완료된 결과, 16수 이상을 요구했다.
출처당 최대 200판을 수열 SHA256 순서로 선택하고, 성능과 무관하게 분할했다.

| 묶음 | 판 | 수 | 용도 |
|---|---:|---:|---|
| dev | 457 | 31,585 | 손실 분석 및 12개 구조 후보 |
| select | 153 | 10,270 | dev에서 고른 후보 3개 비교 |
| sealed | 154 | 10,646 | 후보 고정 후 처음 평가 |
| source_holdout | 285 | 19,942 | 통째로 제외한 다른 대회 2개 |

기보 단위로 분리했으며 선수 단위 분리는 아니다. dev와 선수 중복은
select 176명, sealed 173명, source_holdout 40명이다. 별도 출처 묶음은
다른 bullet 대회라서 장시간 대국에 대한 외삽 증거로 사용할 수 없다.
UCI 원본, 공개 대국 주소, 헤더, 해시와 분할 규칙은 data-r13에 보존했다.
원본 PGN의 재다운로드 결과가 달라져도 포함한 UCI 스냅샷으로 결과를 재현한다.

## 구조 실험과 결과

250의 학습 계수는 그대로 두고 중반 단계들을 제거하거나 합쳤다.
plan/context/rank/R5/R6/specialist/R10을 각각 제거하고, global+context
CDF를 합치거나 여러 단계를 함께 제거했다. 다른 0~250 포맷은 변경하지 않았다.
전문가 혼합 제거(mask95)가 dev와 select 양쪽에서 유일하게 payload를 줄인
제거 후보였다. 선택용 감소량은 단 3비트였다.
benchmarks-r13/FREEZE.json에 설정을 고정한 뒤 두 보류 묶음을 평가했다.

| 묶음 | 기존 250 payload bit | mask95 payload bit | 변화 | 실제 파일 byte 변화 |
|---|---:|---:|---:|---:|
| dev | 107,323 | 107,294 | −29 | −3 |
| select | 35,313 | 35,310 | −3 | 0 |
| sealed | 36,474 | 36,477 | +3 | +1 |
| source_holdout | 69,198 | 69,146 | −52 | −5 |

두 보류 묶음을 별도 파일로 합산하면 105,672→105,623 payload bit,
13,687→13,683 byte다. 일반화된 개선이라고 단정하기에는 매우 작고,
sealed에서는 오히려 커졌다. 251에는 mask를 위한 1byte가 추가되며,
실제 파일 크기는 이 비용과 개별 byte 반올림까지 포함한다.
보류 자료를 보고 설정을 다시 조정하지 않았고 고정 프리셋 252는 만들지 않았다.

## 수별 손실에서 확인한 다음 개선 대상

개발용 31,585수를 234와 250으로 짝지어 추적했다. 전체 payload는
109,285→107,323bit다. 250의 평균 중반 손실은 3.47664bit/수였다.
중반의 잡기 없는 룩 이동은 평균 4.86941bit(1,922수), 폰 이동은
4.79642bit(1,972수)였다. 6bit 이상인 사례는 각각 479수와 461수다.
따라서 다음 실험은 이 두 부류에서 파일·폰 구조·기물 활동성 특징이 기존
단계를 대체할 수 있는지 확인하는 것이 합리적이다. 이 손실 전체를 절감
가능량으로 해석하면 안 된다. 다음 모델에는 새로운 보류 기보가 필요하다.

loss-groups.csv에는 국면/기물/잡기/출처/시간제한/평균 Elo 구간별 합계를,
top-loss-moves.csv에는 손실 상위 100수의 대국 주소와 수를 남겼다.
bits는 최종 CDF의 −log2(p)이며 실제 산술 코더 payload와 framing은 별도다.
in_check는 두기 전 체크 여부, gives_check는 둔 후 체크 여부다.

## 포맷 및 재현

251은 DMTE, version1, profile251이며 기존 6byte 헤더 다음에 mask 1byte가 온다.
mask bits: 1 plan, 2 context, 4 rank, 8 positional R5, 16 R6,
32 specialist, 64 중반 R10, 128 global/context 합치기.
128을 켜면 2도 켜야 한다. 127은 250과 payload가 같고 헤더만 1byte 길다.
128은 두 모델 계수를 합쳐 CDF를 한 번 적용하며 학습 상태 둘은 유지한다.
R5 제거 시 quiet 분류는 유지하고, 단계 제거는 해당 특징 추출 및 학습도 끈다.
오프닝·엔드게임 및 R12 all-phase 범주 모델은 구조 mask의 영향을 받지 않는다.

```bash
python3 tools/reproduce_r13.py --out build-r13 --full --timing
```

g++ C++20과 Python 표준 라이브러리로 스냅샷 실험을 재현한다.
최초 PGN 정제만 python-chess가 필요하며 tools/prepare_r13_data.py에 담았다.
reference-r12는 변경 전 소스이며 같은 O3/FAST_TACTICAL/FEATURE_LUT 옵션으로
컴파일한다. PGO, LTO, opportunity cache는 이번 비교에 사용하지 않았다.
속도는 11라운드의 교대 측정에서 처리량 비율 중앙값을 비교했다.
선택용 153판에서는 인코드 +4.86%, 디코드 +3.57%, 별도 대회 285판에서는
인코드 +5.18%, 디코드 +3.71%였다. 별도 대회에서 후보가 빠른 라운드는
인코드 10/11, 디코드 11/11이었다. 단일 환경 결과이며 실행 편차가 있다.
원시 측정과 범위는 benchmarks-r13/speed-results.md 및
benchmarks-r13/speed-results-holdout.md에 기록한다.

연구 후보를 실제 파일에 적용하려면 다음처럼 실행한다. 기본값은 바뀌지 않는다.

```bash
build-r13/dmg_mid pack r13-no-specialists sample.dmt game1.uci game2.uci
build-r13/dmg_mid unpack sample.dmt restored
```

라이브러리 API는 `mid_encode_structure(games, 95)`이며 디코더가 mask를 읽는다.
프로필 이름 `r13-structure`만 지정하면 127이므로 위 후보 별칭과 구분한다.

## 검증

benchmarks-r13에 새 빌드, 코덱 회귀 테스트, 모든 유효 mask 192개에 대한
빈 아카이브/빈 대국/인간 기보/랜덤 기보 768건 테스트를 남겼다.
왕복 복원, 결정성, mask127/250 payload 일치, CRC, 유효 CRC를 가진 잘못된
mask·version, 모든 길이의 잘린 입력 거부를 확인한다.
기존 0~250의 인간23판·랜덤48판 502개 아카이브는 DMT12와 byte가 같다.
data-audit.json에는 자료 중복·해시·분리 검사를 기록했다.
이전 README-R12 및 이전 benchmarks 폴더는 과거 결과이며 R13 결과와 구분한다.
