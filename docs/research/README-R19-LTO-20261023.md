# R19 link-time optimization experiment — 2026-10-23

This is a separate build-only experiment on the previously validated direct-output implementation. It does not use the optional attack-union or incremental-ray source variants. The baseline is the original `r19_inplace` executable. The candidate compiles `tools/native/r19_inplace.cpp` and `src/rmc.cpp` together with standard `-O3` flags plus `-flto=1`, allowing the compiler to optimize across the board implementation and codec translation units. No source/model/container semantics change.

This intervention enables cross-module optimization; a speed gain alone would not identify which inlining, layout or other compiler transformation caused it. No host-specific instruction-set flag, relaxed floating-point flag or profile-guided training is used.

## Protocol

The fresh output protocol is written before validation/timing. CPU0 is pinned; three datasets each receive four alternating ABBA/BAAB blocks, for 48 actual CLI processes and 12 paired blocks per direction. Each call warms then performs three encode and three decode iterations with validation. Phase wall durations are summed for each label within a block, and throughput ratios are combined geometrically. No build, training, tests or other benchmark runs concurrently with timing.

Before timing, exact archive-byte equality is checked for all five supported modes × all three datasets, and each pack checks its own roundtrip. The candidate also runs the existing 1,226-check suite. Binary and dataset hashes are recorded, and binary hashes are checked after measurement. This experiment is exploratory on one fixed host/core; serial blocks and fixed datasets do not establish statistical significance, general performance, or an independent 60–70K target result.

## Reproduce

```sh
python3 tools/build/build_r19_inplace.py --out build-r19-inplace
python3 tools/build/build_r19_lto.py --out build-r19-lto
python3 tools/benchmarking/benchmark_r19_lto.py --baseline build-r19-inplace/r19_inplace --candidate build-r19-lto/r19_lto --out fresh-lto-study
```

The retained direct-output sources must exist before the LTO build. Ordinary build/compiler changes can alter performance; use the binary hashes recorded in the evidence to identify this run. This study keeps all prior source variants and results, including unfavorable measurements.

## Measured outcome

| Dataset | Encode gain vs direct-output | Decode gain vs direct-output | LTO median encode/decode ply/s |
|---|---:|---:|---:|
| r19 | +2.026% | +8.298% | 47,102 / 47,655 |
| r18 | +6.386% | +2.398% | 52,296 / 50,884 |
| r17 | +2.152% | -1.485% | 49,631 / 49,261 |

Equal-dataset geometric mean gains are encode +3.502% and decode +2.992%. Encoder means improve on all three datasets (9/12 blocks), but the decoder regresses 1.485% on R17 heldout439 (8/12 blocks positive overall). The R17 encoder average includes one +15.0% block with two negative blocks. Therefore these means do not establish a consistently faster both-direction replacement. Keep LTO as an optional build, and retain the standard direct-output baseline. All 15 archive identity cases and 1,226 existing checks pass. Frozen sources/models, source hashes and binary hashes are verified. The general pack default remains profile234. The 60–70K target is not established by these measurements.
