# DMT11 연구: DMT10/234의 출력 유지 최적화와 통합 모델 실험

실행일: 2026-10-22. 기본 프로파일은 **234로 유지**한다. 이 패키지는 새 모델을 기본값으로 승격한 배포가 아니다.

## 결론

- 기존 234의 압축량은 그대로 유지하면서, 세 자료에서 인코딩 처리량 중앙값이 약 8~9% 높아졌다.
- 디코딩은 Human23/WCC13에서 개선됐으나 Random48에서는 거의 같거나 소폭 낮았다. 모든 입력에서 빨라졌다고 주장하지 않는다.
- 새 단순 모델과 통합 모델을 실제 구현했지만 **압축률과 속도의 동시 우위를 입증하지 못했다**. 메인은 234로 유지한다.
- 60~70K 반수/초의 안정적 처리량, 미들게임 3.9비트대 목표는 여전히 미달이다.

## 1. 출력 바이트를 유지하는 변경

1. `OwnAttackReuse`: 한 포지션의 기물별 공격을 캐시한다. 후보 수에서 이동·승격·캐슬링으로 바뀐 기물과 점유 변화의 영향을 받은 슬라이더만 다시 계산한다. 앙파상도 점유 변화에 포함된다.
2. 이미 완전히 합법적인 후보 목록에서 선택한 DMT 수는 보드에 다시 합법성 검사 없이 적용한다. 인코더의 `index_of`는 목록 밖의 불법 입력을 계속 거부한다.
3. 정규화와 잔차 학습의 반복 나눗셈은 정확한 정수 역수 추정과 나머지 보정으로 계산한다. 부동소수점 근사는 쓰지 않으며, 128비트 정수 곱이 없는 컴파일러는 기존 나눗셈을 사용한다.
4. 오프닝 사전을 전체 키의 동등성 검사를 유지하는 해시 테이블로 변경했다. 퇴출은 기존 삽입 순서 그대로이며 해시 테이블 순회 순서는 부호화에 사용하지 않는다.
5. 전문가 혼합의 후보 공통 나눗셈을 루프 밖으로 이동했다.

각 변경의 독립적인 속도 기여를 분리 측정한 것은 아니다. 아래 수치는 변경 묶음 전체의 효과다. `DMT_REFERENCE_RELATIONS` 옵션으로 공격 맵 재사용만 원본 경로로 되돌릴 수 있다.

## 2. 같은 환경에서 측정한 처리량

단위: 반수/초. 원본 234 → 최적화한 234.

| 자료 | 인코딩 | 변화 | 디코딩 | 변화 |
|---|---:|---:|---:|---:|
| human23 | 52,844 → 57,167 | +8.2% | 54,809 → 56,019 | +2.2% |
| wcc13 | 51,201 → 55,856 | +9.1% | 52,360 → 58,620 | +12.0% |
| random48 | 44,518 → 48,507 | +9.0% | 45,883 → 45,635 | -0.5% |

각 셀은 별도 실행 3회의 중앙값이다. 한 실행은 워밍업 후 7 trial × 인코딩/디코딩 각 8회를 수행하고 중앙값을 반환한다. 원본과 수정본은 같은 `g++ -O3` 플래그로 빌드했고 실행 순서를 번갈아 배치했다. 측정 중 이 작업의 다른 컴파일은 실행하지 않았다. `-march=native`는 사용하지 않았다.

공유 환경의 부하·주파수·스케줄링 편차가 크며 원본/수정본의 실행별 범위가 겹친다. 통계적 유의성이나 전용 하드웨어에서의 속도 보장은 주장하지 않는다. 기존 보고서의 45K 수치와 이번 원본의 51K 등을 직접 비교하지 않는다. 원시 결과는 `benchmarks-r11/speed.csv`, 환경은 `environment.json`에 있다.

## 3. 새 모델 6개

새 스트림은 `DMTB` 및 ID 243~248로 분리했다. 구버전의 `DMTA`는 189~242만 허용한다.

| ID | 구조 | 인간 개발 3자료 합산 비트 | 234 대비 |
|---|---|---:|---:|
| 234 | 기존 전문가 혼합 + 보정 | 12,994 | 기준 |
| 243 | DMG8 관계 모델 + 저비용 10특징 잔차, 학습률 2 | 13,650 | +656 |
| 244 | 같은 구조, 학습률 4 | 13,635 | +641 |
| 245 | 기존 공통 기반 + 전문가 30특징의 단일 로그선형 잔차, 학습률 2 | 13,021 | +27 |
| 246 | 같은 구조, 학습률 4 | 13,029 | +35 |
| 247 | 30특징 + 후보 보정 10특징을 한 분포로 공동 학습, 학습률 2 | 12,997 | +3 |
| 248 | 같은 40특징 구조, 학습률 4 | 13,001 | +7 |

245~248은 오프닝·엔드게임을 234와 동일하게 유지하고 미들게임의 전문가 혼합을 대체한다. 공통 기반에는 기존 보정 모델이 남아 있으므로 전체 코덱이 단 하나의 모델로 바뀐 것은 아니다. 오프라인 증류나 외부 학습 가중치는 사용하지 않았다.

247은 Human23에서 6,497→6,495비트로 줄었지만 Human4는 1비트, WCC13은 4비트 늘었다. Random48도 23,507→23,516비트로 증가했다. 개발 표본의 2비트 절약을 일반적인 개선으로 해석하면 안 된다. 통합 모델의 속도도 자료·실행에 따라 들쭉날쭉해 메인 교체를 정당화하지 못했다.

이 수치는 산술 부호화 페이로드이며 헤더·CRC는 제외한다. 실제 파일 바이트 수와 국면별 로그손실도 `compression.csv`에 함께 있다.

## 4. 검증

- 기본 234의 암시적/명시적 선택 일치, 구버전 왕복, CRC 거부: PASS.
- DMT10의 대표/신규 64개 프로파일: Human23, 랜덤 8판, 빈 아카이브, 결정성, CRC, 골든 9개: PASS.
- DMT11 신규 6개 프로파일: 동일한 왕복·결정성·CRC 검사와 구버전 골든 9개: PASS.
- 독립 공격 커널 검사: 합법 후보 공격 맵 **543,150개**, 캐슬링 양측·앙파상 양측·승격 포함, 전체 재구축과 일치.
- 정수 나눗셈 커널: **160,000개** 무작위·경계값 검사에서 원본 나눗셈과 일치.
- 기존 core/V6/V7/V8/V9/phase 및 공격 오라클 테스트: PASS. 기존 공격 오라클은 17,967포지션, 2,299,776개 칸/진영 질의를 검사했다.
- 원본 실행 파일과 수정 실행 파일의 기존 243개 프로파일을 Human23 및 Random48에서 각각 바이트 단위 비교: 결과는 `compatibility.json` 참조.

CMake가 설치되어 있지 않아 직접 g++로 빌드·실행했다. 따라서 `ctest` 전체 통과라고 주장하지 않는다. 기존의 오래 걸리는 `dmg_mid_roundtrip` 전체 테스트도 실행하지 않았으며, 위의 전체 프로파일 두 코퍼스 비교와 집중 검사를 수행했다. 사전의 32,768항목 퇴출 한도 초과 상황은 별도 스트레스 검사하지 않았다.

## 5. 데이터 해석과 남은 과제

Human23/Human4/WCC13은 반복 사용된 개발 자료다. Fischer3도 이전 연구에서 이미 사용됐으므로 이번 결과에서는 `fischer3_reused`로 표시했다. 새로운 독립 인간 대국을 확보하지 못했으며, 일반화 개선은 입증하지 않았다.

이번 구현에서 목적지 보정은 부호화 순서를 바꾼 것이 아니다. 특히 체크·SEE 특징은 출발 기물에 따라 달라진다. 이에 맞게 기존 코드 주석도 수정했다.

압축률의 다음 판단에는 새 인간 대국을 분리한 검증셋이 먼저 필요하다. 현재 결과만으로는 특징이나 학습률을 더 탐색할 근거가 약하다. 속도는 공격 맵과 공통 기반 모델이 여전히 남아 있어, 작은 단일 잔차로 전문가 혼합만 바꾸는 것으로 큰 상승을 기대하기 어렵다.

## 6. 재현

프로젝트 루트에서:

```bash
python3 tools/build/build_r11.py --out build-r11
python3 tools/reproduction/reproduce_r11.py --build build-r11 --out reproduced-r11
python3 tools/analysis/compare_r11.py --build build-r11 --out comparison-r11 --speed
```

`compare_r11.py`는 동봉한 `reference-dmt10`의 원본 소스를 빌드해 전체 243개 프로파일의 실제 아카이브 바이트를 비교한다. 이 디렉터리는 최적화 전 원본이다. 기본 234 및 새 후보의 사용 예:

```bash
./build-r11/dmg_mid main
./build-r11/dmg_mid pack result.dmt examples/heldout/*.uci
./build-r11/dmg_mid pack r11-joint40-rate2 candidate.dmt examples/heldout/*.uci
./build-r11/dmg_mid unpack candidate.dmt recovered
```

CMake 환경에서는 기존 빌드 경로도 유지한다. 신규 타깃은 `dmt11_tests`, `dmt11_kernel_tests`, `dmt11_audit`다. 커널 검사는 비공개 구현을 포함하는 독립 번역 단위로 빌드한다.
