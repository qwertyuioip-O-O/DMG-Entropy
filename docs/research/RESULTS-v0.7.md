# DMG-Entropy v0.7 — 구현·검증 보고서

## 결론

**모델 경쟁형 압축은 v0.6부터 이미 구현되어 있었습니다.** 당시 `mixture`는 전술+균등+계층형이고 `all`은 여기에 정확한 포지션 사전을 추가했습니다. v0.7은 **동일 포지션이 아니어도 공유 가능한 두 사전**을 추가하고, 이를 온라인 모델 경쟁에 포함시켰습니다.

그 결과, 패턴 단순 출현 빈도는 크게 실패했습니다. 그러나 **기회 보정 확률 사전**은 기존의 23개 실전 대국에서 `4.2346 → 4.1240 bit/반수`로 개선됐습니다. 기존 최상위 대비 이동 데이터 약 **2.61%**, 실 저장 파일 `947 → 923바이트`입니다. 성능은 실측이며 일반 전체 대국으로 일반화된 주장은 아닙니다.

## 재현 데이터

같은 소스, `CMAKE_BUILD_TYPE=Release`, 전체 아카이브를 압축/해제하는 처리량. 초당 백만 반수 처리량(Mply/s). 내장 벤치마크는 중앙값 기준이며 실행 환경 노이즈가 존재합니다.

## 검증

- v0.7 모든 모드, 0게임, 빈 게임, 반복 게임, 무작위 합법 게임: 압축→복원과 바이트 재현성 성공
- v0.7 테스트에서 아카이브의 각 바이트를 1비트 반전시켜 CRC32 손상 검출 확인
- 기존 v0.6의 실제 `heldout23-dictionary.dmg6` 파일을 DMG7 CLI로 복원 후 23개 원본 UCI와 비교해 일치
- 23게임 auto 컨테이너 생성→CLI 복원→원본 UCI 전수 대조 성공
- CTest 3/3 통과, 별도 ASan·UBSan 빌드에서도 3/3 통과

## 모델 경쟁 관련 명확한 구분

- **온라인 혼합**: 산술 부호화 확률을 여러 모델의 가중 평균으로 계산하고, 착수 복원 후 가중치를 갱신합니다. 모델 선택 비트가 없어도 양쪽이 동일 상태를 유지합니다. `competition`, `switching`, `opportunity-competition`, `selective-competition`이 해당됩니다. 최상위 전문가보다 비트 수가 나쁠 수 있습니다.
- **아카이브 단위 auto**: 입력 전체를 여러 번 압축한 후 실제 총 바이트 수가 가장 작은 아카이브를 저장합니다. 반환 파일에 최종 모델 ID가 이미 들어 있어서 별도의 선택 부호화가 필요 없습니다. 인코딩은 매우 느리지만 디코딩은 선택된 단일 모델만 계산합니다. 출력 매직은 `DMG6` 또는 `DMG7`이 될 수 있습니다.

## 한계와 다음 과제

- 23개 실전 대국은 이전 여러 차례의 알고리즘 검토에서 반복 사용했으며, 이번 개선의 하이퍼파라미터(기회 보정 prior/클립)도 실험하며 정했습니다. **대규모 홀드아웃 검증 전까지 일반화가 입증되었다고 말할 수 없습니다.**
- 현 C++ 구현의 키·사전은 인코더·디코더가 완전한 공통 상태를 재생하지만, 대규모 DB에서 메모리 사용량이 계속 증가합니다. 맵 제한·리셋·인덱싱이 필요합니다.
- 후보 생성과 체크 유발 여부 검사 비용이 커서 대용량 아카이브에서는 속도 향상이 필요합니다.
- 아카이브 단위 auto는 매우 긴 입력에 과도하게 느릴 수 있습니다. 현실적인 대안은 게임 블록별 명시적 모델 선택과 독립적으로 디코딩 가능한 청크입니다. 게임 블록마다 새 모델/사전 상태를 정의해야 합니다.
- 전체 게임의 개별 랜덤 액세스, 주석/태그와 비표준 시작 FEN, Chess960은 아직 지원하지 않습니다.
- 완전히 새로운 압축 이론을 증명한 것은 아니며, 기존 문맥 적응·기회 대비 관측 빈도·온라인 전문가 혼합을 체스 후보 공간에 적용한 실험입니다.
