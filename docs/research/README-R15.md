# DMT15 — 폰 전진·잡기 범주 분리 실험

2026-10-22. **폰 잡기의 손실은 회복했지만 전체 압축 이득은 작아 채택을 보류했다.**
기본값234와 기존 후보252를 유지한다. 새253은 재현 가능한 연구용 선택지다.
새 대회476판에서 R14/252 대비 payload17bit, 실제 파일2byte를 줄였다.

## 무엇을 바꿨나

R14는 폰 전진과 잡기에서 같은 구조 범주 계수를 공유했다.
우선 기존4분류·8분류를 전진/잡기에 나누어 쓰는 작은 변경을 비교했다.
모든 입력에서 복원할 수 있지만 특징을 거칠게 만드는 비용이 있어,
개발 자료에서 가장 좋은 compact split의 감소도8bit에 그쳤다.

이어서 표준 체스 합법 수에서 사용되지 않는 거리 범주를 재활용했다.
나이트의 Chebyshev 이동거리는 항상2이고, 킹은1 또는 캐슬링 때2다.
따라서 다음12개 계수 주소는 기존 중반 거리 모델에서 실제 수가 사용할 수 없다.

- 잡기 전용 중앙성4칸:104,105,107,108
- 잡기 전용 거리8칸:109,110,111,136,139,140,141,142

일반 나이트 거리 주소106, 일반 킹 거리 주소137/138과 겹치지 않는다.
다른 기물의 거리 주소와도 겹치지 않는다. 이12칸에 폰 잡기의 기존 특징을
옮겨, 폰 전진의 구조 범주를 그대로 보존하면서 따로 학습했다.
**배열은 기존168계수/국면을 유지하지만, 이전에 비활성인12계수가 새로 활성화된다.**
분포 보정 단계를 추가하지 않았으며 오프닝·엔드게임도 바꾸지 않았다.

## 후보와 선택

총24개 설정을 개발457판에서 비교했다.
첫15개는 대조군, 적용범위 변경, compact split 및 잡기 계수 학습률1/2/4다.
추가9개는 full-resolution split, 잡기에서 예전 기하 특징으로 복귀,
잡기 뒤 출발 파일 개방·통과폰 변화를 반영한 특징 × 잡기 학습률1/2/4다.
모든 설정의 일반 중반 학습률은1로 같고 룩 특징과 나머지 구조는 R14 그대로다.

개발 자료에서 실제 byte/bit 순 상위3개(7:2,7:4,2:1)를 선택153판에서 비교했다.
선택 자료에서 가장 작은 mode7/rate1/capture_rate4를 고정했다.
R14는35,177bit/4,573byte, 후보는35,175bit/4,572byte로 이득은2bit에 불과했다.
FREEZE.json을 작성한 뒤 새 보류 자료와 WCC를 평가했으며 이후 설정을 조정하지 않았다.

## 새로운 보류 자료

이전 대회와 다른 완료된 Lichess 대회4개에서476판/33,299수/513명을 확보했다.
3/5/10분 계열이다. 표준 초기 배치, 완료 결과,16수 이상, 파싱 오류 없는
대국만 사용했다. 모든 이전 UCI 수열과 같은 대국 및 신규 내부 중복은 제거했다.
출처당 최대120판을 UCI SHA256 순서로 선택했고 성능 지표로 자료를 고르지 않았다.
선수는 dev와14명, select와8명이 겹치므로 선수 단위 분리는 아니다.
공개 대국 주소·헤더·해시·출처를 data-r15에 담았으며 스냅샷 UCI가 재현 기준이다.

| 묶음 | R14/252 bit | 새253 bit | R14→253 byte |
|---|---:|---:|---:|
| dev457 | 106,751 | 106,742 | 13,833→13,832 |
| select153 | 35,177 | 35,175 | 4,573→4,572 |
| 새 heldout476 | 111,296 | 111,279 | 14,420→14,418 |
| 이전 R14 heldout395 | 91,040 | 91,037 | 11,814→11,814 |
| 이전 R13 sealed154 | 36,345 | 36,343 | 4,720→4,719 |
| human4 | 1,925 | 1,925 | 263→263 |
| WCC13 | 4,494 | 4,494 | 593→593 |

새476판의 중반 CDF 손실은3.375284→3.374222bit/수다.
오프닝3.506089, 엔드게임3.009411은 같다.
새 대회를 각각 처음부터 학습하는 별도 아카이브로 비교하면 payload 변화는
blitz1700 −7bit, blitz_open −5bit, rapid1500 0bit, superblitz_open −2bit다.
출처별 초기화 결과의 합과 전체476판 결과는 학습 경로 및 framing이 달라 직접 같지 않다.
과거 묶음 결과는 새 독립 검증 표본 수에 더하지 않았다.

## 손실 회복과 전체 이득이 다른 이유

개발 자료31,585수를 동일 수 단위로 짝지어 분석했다.

| 중반 수 부류 | 같은 학습률1에서 분리만 한 변화 | 선택한 잡기 학습률4 설정의 변화 |
|---|---:|---:|
| 폰 잡기971수 | −33.09bit | −27.25bit |
| 잡기 없는 폰 이동1,972수 | +6.52bit | +2.39bit |

선택된 설정은 R14에서 늘었던 폰 잡기 손실을 개발 자료에서 거의 회복했다.
그러나 합법 수 전체의 확률을 함께 정규화하고 다른 모델도 온라인으로 갱신하므로,
특정 부류의 이득이 전체 bit 감소량과 같지 않다. 다른 수들의 증가가 상쇄해
전체 개발 payload 감소는9bit였다. 잡기 학습률4는 폰 잡기 부류만 보면1보다
나빴지만, 전체 선택 파일을 기준으로 선택되었다. 선택 차이가 극히 작다는
사실 자체를 설정의 불안정성과 함께 기록한다.

## 속도와 판단

250, R14/252, 새253을 같은 O3 빌드에서12라운드로 교대 측정했다.
세 모델의 실행 위치·순서를 균형 있게 바꾸고 인코드/디코드를 각2회 반복했다.
선택 묶음과 새 보류 묶음을 모두 측정하며, 다른 컴파일·테스트는 먼저 종료했다.
측정 중에도 인코드 결정성과 디코드 결과를 확인했다.
benchmarks-r15/speed-results.md와 speed-summary.json에 비율·범위·절대 처리량을,
speed-select.csv와 speed-heldout.csv에 원시 wall/CPU 시간을 남겼다.
단일 공유 환경 결과이며 여러 하드웨어에 대한 속도 보장은 아니다.

R14/252 대비 처리량 비율의 중앙값은 select에서 인코드+1.78%, 디코드−0.02%,
새 heldout에서 인코드+0.46%, 디코드+0.90%였다. 새 보류 묶음에서 후보가
빠른 라운드는 각각7/12로, 뚜렷한 속도 개선으로 해석하지 않는다.
절대 처리량 중앙값은 새 보류 묶음에서 약62,540/63,307수/초(인코드/디코드)였다.
라운드별 비율의 중앙값과 절대 처리량 중앙값끼리의 비율은 다른 통계량이다.

전체 크기 이득이2byte라서 이번 설정을 기존 후보252의 대체 기본값으로 삼지 않았다.
이번 결과는 간섭을 줄이는 효과가 있더라도 다음 큰 개선의 충분조건은 아니라는 증거다.

## 포맷과 사용

253의 magic은 `DMTG`, version1, profile253이다. 기존6byte 헤더 다음
mode/rate/capture_rate 3byte를 기록한다. 252와 설정 헤더 길이가 같아서
새 보류 자료의2byte 차이는 헤더 길이 축소에서 나온 것이 아니다.
structure95, R14 features7을 고정하고 일반 중반 rate와 잡기 전용 rate를 분리한다.
오프닝·엔드게임은 R14의 rate4를 유지한다.

- mode0: R14 그대로. rate1이면252와 payload가 같다.
- mode1: 폰을 잡는 수만 예전 기하 특징으로 되돌리기.
- mode2: 중앙성4칸을 전진2/잡기2로 분리.
- mode3: 거리8칸을 전진4/잡기4로 분리.
- mode4/5: 양쪽을 분리하고 파일 개방/지원/통과폰 특징 배치를 달리하기.
- mode6: 폰 특징 전체를 예전 기하 특징으로 되돌리기. 룩은 유지.
- mode7: 미사용12칸을 재활용하여 기존 폰 특징을 전진/잡기에 완전히 분리.
- mode8: 같은 전용 칸에서 폰 잡기를 예전 기하 특징으로 사용.
- mode9: 같은 전용 칸에서 파일 개방·통과폰·지원 특징으로 교체.

유효 mode는0~9, 두 rate는1~16이다. capture_rate는 분리된 계수 칸에만 적용한다.
따라서 전용 칸이 없는 mode0/1/6에서는 capture_rate가 결과를 바꾸지 않는다.
실험 API의 기본 설정과 명시적253은 고정된7/1/4다. 일반 pack 기본234는 그대로다.

```bash
python3 tools/build_r15.py --out build-r15
build-r15/dmg_mid pack r15-pawn-split sample.dmt game1.uci game2.uci
build-r15/dmg_mid unpack sample.dmt restored
```

라이브러리 API: `mid_encode_pawn_split(games, {7,1,4})`.
일반 pack, 기존252 및 모든 과거 포맷은 계속 사용할 수 있다.

## 검증·재현

기존0~252의 인간23판·랜덤48판 아카이브506개가 DMT14와 byte 단위로 일치한다.
기본값, R10~R15 및 전체254프로필 회귀 테스트를 통과했다.
새 테스트는12개 의미 검증과 색상/상하 반전, 전용 칸의 충돌 부재,
60설정×빈 아카이브/빈 대국/인간/랜덤의240건, 결정성·왕복 복원,
mode0/252 payload 일치, CRC, 유효 CRC를 가진 잘못된 설정·version,
모든 길이의 잘린 입력 거부를 포함한다.

```bash
python3 tools/reproduce_r15.py --out build-r15 --full --timing
python3 tools/analyze_r15_losses.py
```

전체 재현은 g++ C++20과 Python 표준 라이브러리를 사용한다.
prepare_r15_data.py의 최초 PGN 정제에만 python-chess가 필요하다.
포함된 UCI 스냅샷만으로 코덱 결과를 재현할 수 있다.
reference-r14는 변경 전 소스이며 PGO/LTO/opportunity cache는 사용하지 않았다.
이전 README 및 benchmarks 폴더는 과거 기록이다. 이번 결과는 benchmarks-r15다.
