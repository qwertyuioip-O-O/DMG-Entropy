# DMT18 — 문맥별 사전 학습 보정과 제한된 온라인 적응 검증

2026-10-22. R17 고정 사전 학습 모델 위에 포획/도착 칸 공격 여부별 보정값을 추가했다.
새456판에서 실제 파일12,977→12,888byte(0.686%)를 확인했다. 세계선수권13판 중반은3.98508→3.93231bit/반수로 개선했으나3.9 이하 목표는 미달이다.
이번 측정에서는 속도 우위가 없었다. 새 후보는 압축 우선 연구 옵션이며 기존 일반 pack 기본234와 R17 옵션을 유지한다.

## 두 가설과 선택

첫 가설은 R17 사전 학습값을 중심으로 작은 온라인 잔차만 허용하는 것이었다. R13 select153판에서 다음8개를 비교했다. 잔차는 기존과 같은 정수 기대값 갱신을 쓰고, 일정 주기마다0 쪽으로1씩 줄인다. 보정값 자체를0으로 잊는 대신 사전 학습값을 유지하려는 설계다.

| mode | 학습률 | 잔차 제한 | 감쇠 주기(중반 반수) |
|---|---:|---:|---:|
| 1 | 1 | ±8 | 64 |
| 2 | 1 | ±16 | 64 |
| 3 | 1 | ±32 | 256 |
| 4 | 1 | ±64 | 1024 |
| 5 | 2 | ±16 | 64 |
| 6 | 2 | ±32 | 256 |
| 7 | 2 | ±64 | 1024 |
| 8 | 1 | ±32 | 64 |

선택용 결과는 기존 고정 모델34,818bit에 비해34,822~34,885bit로 모두 나빠 채택하지 않았다. 결과는 select-anchor.csv다. 세계선수권 결과에 맞춰 이 설정을 골라 바꾸지 않았다.

두 번째 가설은 같은 거리/중앙성/도착 rank라도 문맥에 따라 뜻이 다르다는 것이다.
기존 전술 플래그에서 `capture`와 이동 후 도착 칸의 `square_attacked`를 읽어 후보마다4개 문맥(조용한 수/포획 × 공격받음/아님)을 만든다. 추가 체스 탐색이나 공격 맵 계산은 하지 않는다.
기존5범주의 각168계수 배치를 문맥별로 복제해672개 고정 잔차를 학습한다. 후보의 기존5개 키로 해당 문맥 테이블5개 값을 더하고 ±128로 제한한 뒤 기존 LUT를 적용한다. R17 보정 후 분포에 추가로 적용/정규화하는 두 단계다.
기존 전역168계수336byte에 문맥672계수1,344byte가 추가된다. 모두 int16 고정 테이블이며 매 아카이브에 쓰지 않는다. 같은 테이블을 가진 디코더가 필요하다. 모델을 파일마다 별도 배포하면 그 비용을 추가해야 한다.

- 학습은 R13 dev457판/31,585반수 중 중반14,330위치/470,656후보만 사용했다. 입력 분포는 R17 고정 모델로 실제 재생하면서 추출했다.
- 정규화1e-4/1e-3/1e-2의3개 테이블을 학습하고, R13 select153판만으로 고른다. 총8개 온라인 후보+3개 문맥 후보다.
- 1e-4는300회 반복 제한에 도달했고 수렴으로 표시하지 않았다. 선택된1e-3은70회에 수렴했다. 계수 범위는 -72..57이다.
- 선택된 mode9/1e-3은 선택용34,818→34,587bit,4,529→4,500byte였다. FREEZE.json에 모델 해시를 기록한 뒤 새 기보를 평가했다. 이후 모델/문맥/하이퍼파라미터는 바꾸지 않았다.
- 오프닝/엔드게임 및 R17 기반 모델의 온라인 적응은 유지한다. 추가 문맥 모델은 고정이며 온라인 계수 갱신을 하지 않는다.

## 실제 압축 결과

기준은 R17 고정 사전 학습 모델(mode2)이다. 새 D18P와 기존 D17P의 프레이밍 길이가 같아 아래는 헤더/게임 길이/CRC까지 포함한 실제 파일 비교다. 기존 R17 실행 파일로 기준 파일도 직접 생성했다.

| 자료 | R17 byte | R18 byte | 감소 | R17 중반 bit/반수 | R18 중반 |
|---|---:|---:|---:|---:|---:|
| 새456판: 동결 후 평가 | 12,977 | 12,888 | 0.686% | 3.30488 | 3.25050 |
| 세계선수권13판: 회귀 | 585 | 581 | 0.684% | 3.98508 | 3.93231 |
| 이전439판: 회귀 | 12,751 | 12,658 | 0.729% | 3.32212 | 3.26517 |
| 이전202판: 회귀 | 6,285 | 6,237 | 0.764% | 3.34831 | 3.28716 |
| 이전476판: 회귀 | 14,292 | 14,177 | 0.805% | 3.30656 | 3.24590 |
| 인간4판: 회귀 | 262 | 262 | 0.000% | 4.06395 | 4.06370 |

인간4판은 파일 크기가 같고 payload는1,907→1,908bit로1bit 늘었다. 모든 자료에서 비트가 줄었다고 주장하지 않는다.
세계선수권의 R16 strong 결과4.08905bit/반수와 비교하면 R17을 거쳐3.93231까지 내려왔지만, 현재13판을 여러 연구에서 확인했으므로 이 자료는 독립 검증이 아니다. 목표3.9 이하도 아직 달성하지 못했다.

## 보정 범위 확대와 문맥 효과를 구분했다

두 번째 보정 단계는 문맥뿐 아니라 전체 확률 보정 범위도 넓힌다. R18에서는 각 단계가 별도로±128로 제한되어, 단순히 기존 R17보다 전체 점수 범위가 넓어진 효과가 섞일 수 있다. 이를 확인하기 위해 추가 대조군을 만들었다.
기존 R17 위에 똑같은 추가 LUT/정규화 단계를 쓰되,4개 문맥의 계수를 묶어168개만 공유한다. 파일에는 동일한 값을4번 복제해 동일한 코덱 경로로 실행했다.
대조군도 dev만 학습하고 select153만으로 정규화1e-4/1e-3/0.004/1e-2를 선택했다. 0.004는 문맥 모델의0.001 페널티에서 네 테이블을 묶었을 때의 대응값이다. 선택된 대조군은1e-4, 선택용34,785bit다.

| 자료 | R17 payload bit | 문맥 없는 추가 보정 bit | 문맥 보정 bit | 문맥 없는 보정 byte | 문맥 보정 byte |
|---|---:|---:|---:|---:|---:|
| new | 99,869 | 99,748 | 99,158 | 12,962 | 12,888 |
| wcc | 4,423 | 4,408 | 4,391 | 583 | 581 |
| r17 | 98,215 | 98,106 | 97,467 | 12,738 | 12,658 |

새456판에서 단순 추가 보정의121bit 절감보다 문맥 보정의711bit 절감이 컸다. 추가 단계만으로 설명되지 않는590bit 차이를 관측했다.
단, 이 대조군은 첫 새 평가 결과를 본 후 추가한 사후 진단이다. 대조군의 학습/선택에는 새 자료를 사용하지 않았지만, 완전히 사전 등록된 독립 비교라고 부르지 않는다. POSTHOC-CONTROL-FREEZE.json과 별도 선택/학습 로그를 남겼으며 기존 동결 후보를 바꾸지 않았다.

## 새 자료와 작은 파일

새 자료는 종료된 대회4개(anBGyp2p/eFHCBwkf/FVGijE19/k8MhGhZy)의456판/30,319반수/530명이다. 3분·3분+2초·10분 계열과 등급 제한 대회를 포함한다. 출처당 최대120판을 UCI SHA256 순서로 선택했다.
표준 초기 배치·완료 결과·16반수 이상·파싱 오류 없는 게임만 사용했다. 이전 전체 UCI 수열 및 내부 중복은0이다. 선수 중복은 dev15명/select6명으로 선수 단위 독립 자료는 아니다. 공개 온라인 대국에 대한 결과이며 모든 수준의 체스를 대표하지 않는다.
공개 API 주소, 다운로드 해시, 대회 완료 여부, 기보 헤더/해시와 고정 UCI를 data-r18에 포함했다. 모든 과거 평가 출처와 다른 대회를 사용했으며 추가 가중치는 dev/select만 사용했다.
각 대회를 따로 초기화해 압축해도4개 모두 파일이 작아졌다. 합친 파일과 별도 파일은 기반 온라인 학습 경로가 달라 합산 비트가 같지 않다.
새456판을 파일당1/10/30/120/456판으로 나눠 초기화했다. 같은 자료의 특성 분석이며 추가 독립 검증은 아니다. 한 판씩 압축한 합계22,540→22,421byte, 중반3.61356→3.53389bit/반수다. 나머지 결과와 복원 검사는 blocks.csv에 있다.

## 속도와 한계

모든 빌드/검사 종료 후 같은 실행 파일의 R17 항등 대조(mode0)와 새 문맥 모델(mode9)을6회 순서를 번갈아 측정했다. 각 프로세스는 예열 복원 후 인코딩3회·디코딩3회와 결과 검사를 수행했다. 파일 로딩은 시간 밖이며 병렬 빌드/학습/검사를 하지 않았다.

| 자료 | 인코딩 처리량 변화 짝별 중앙값 | 디코딩 처리량 변화 짝별 중앙값 | 새 모델 인코딩/디코딩 반수/초 중앙값 |
|---|---:|---:|---:|
| new | -1.16% | -2.37% | 45,729 / 46,493 |
| r17 | -2.48% | +0.78% | 46,346 / 46,152 |

속도 개선을 주장하지 않는다. 새 자료에서는 인코딩/디코딩 각각2/6회만 빨랐고 중앙값은 낮았다. 추가 후보별5개 조회와 두 번째 정규화가 들어간다. 짝별 변화의 중앙값과 별도로 계산한 절대 처리량 중앙값은 동일한 비율이 아니다.
이번 호스트에서는 절대 처리량60~70K 목표를 확인하지 못했다. 같은 시점 원래 R17 실행 파일도 대체로4만대였으며, 원래 R17/새 래퍼 대조/새 후보를3회 순서를 돌려 측정한 native-speed-diagnostic.csv를 남겼다. 지난 실험의6만대와 이번 절대 숫자를 환경 차이 없이 직접 비교하지 않는다.
압축 우선 후보로만 제공하고 기본 모델은 바꾸지 않았다.

## 형식/호환/검증

- 새 D18P v1은 mode0..9와 추가 테이블 CRC32 식별값, 전체 파일 CRC를 사용한다. R17 기본 모델은 형식 버전에 고정되어 있고 추가 테이블은 builtin 또는672개 정수 파일로 제공한다. CRC는 보안 해시가 아니다.
- mode0은 R17 고정 모델의 payload와 완전히 동일하다. mode9에서 추가 테이블이 전부0이어도 payload 항등성을 확인한다.
- 이전 src/include16개 파일은 R17과 바이트 단위로 같다. R17 도구에는 재사용할 때 main을 제외하는 전처리 가드만 추가했고 계산 함수와 기존 형식 의미는 유지했다.
- 새 도구912개 검사:0..9모드 복원, 빈 묶음·빈 판·한 수·인간 기보, CRC 변경, 잘린 입력, 틀린 테이블, 기존 R17 및0테이블 항등성. 실제 학습된 테이블로 최종 빌드에서 통과했다.
- 새/과거 회귀/출처별 평가에서 결정성과 복원을 확인했다. 최종 평가 표와 처음 평가 표가 일치했다.
- 새456판/세계선수권/이전439판의 실제 pack/unpack UCI와 builtin/파일 계수의 전체 파일 일치도 확인했다. 이전508개 호환 검사 전체를 다시 돌렸다고 주장하지 않는다.
- 모델 동결 뒤의 수정은 동일한 builtin 테이블 제공과 테스트/블록/CLI 연결이며 모델 가중치/문맥 정의/설정은 바꾸지 않았다.

## 실행

빌드는 Python3와 g++ C++20이면 된다. 학습 재현에만 NumPy/SciPy, PGN 준비에만 python-chess가 추가로 필요하다.

```bash
python3 tools/build/build_r18.py --out build-r18
build-r18/r18_prior pack data-r18/heldout.uci-bundle builtin 9 result.d18
build-r18/r18_prior unpack result.d18 builtin decoded.uci-bundle
build-r18/r18_prior test benchmarks-r4/human4.uci-bundle builtin
python3 tools/reproduction/reproduce_r18.py --out build-r18 --blocks --controls --timing
# 선택 사항: dev로만 다시 학습
python3 tools/reproduction/reproduce_r18.py --out build-r18 --retrain --controls
```

재현 스크립트의 전체 빌드 포함 실행을 한 번에 다시 돌리지는 않았다. 최종 빌드 후 동일 실행 부분을 순서대로 수행했으며, 선택/학습/사후 대조군/실제 파일 검증은 별도로 실행해 로그를 남겼다. SciPy 버전의 마지막 반올림 차이가 있을 수 있으므로 frozen 텍스트와 builtin 해시를 기준으로 비교한다.

## 판단

문맥별 사전 학습은 R17 위에서 추가 압축 이득을 냈고, 단순히 보정 단계를 하나 더 둔 효과보다 컸다. 제한된 온라인 적응은 선택용 자료에서 실패했다. 전체 파일 감소는 약0.7%로 획기적 수준이라고 부르지 않는다. 세계선수권3.9 이하와 안정적인60~70K 처리량 모두 남아 있다.
