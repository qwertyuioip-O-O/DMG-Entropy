# DMT14 — 룩·폰 구조 특징 교체

2026-10-22. 기존 범주 모델의 특징을 바꿔 **압축량을 줄이는 후보 252**를 구현했다.
기본값 234는 유지한다. 이전 압축 우선 선택지 250도 남겨 둔다.
새 후보는 큰 온라인 기보 묶음에서 유리하지만 모든 기보에서 우세하지는 않다.

## 구현

R13의 전문가 혼합 제거 구조(mask95)를 바탕으로, R12 범주 모델의
중앙성·이동거리 두 칸을 중반의 룩·폰에 대해서만 다른 의미로 대체했다.
학습 파라미터 수는 기존과 같다. 새 분포 보정 단계나 모델을 추가하지 않았다.

- 룩: 목적지 파일에 아군/적군 폰이 있는지, 자기 진행 방향 앞에 폰이 있는지,
  파일을 바꾸는 이동인지.
- 폰: 아군 폰의 지원 여부와 앞쪽 적 폰, 고립폰·중복폰·통과폰 여부.

한 포지션에서 파일별 폰 rank mask를 만들고, 각 합법 후보 수를 둔 뒤의
폰 배치를 계산한다. 폰 잡기, 앙파상, 승격도 반영한다.
중앙성 칸은 4분류, 거리 칸은 8분류를 유지한다. 나머지 기물 및
오프닝·엔드게임의 특징은 기존 그대로다. 중반 범주 모델의 학습률만 4→1로
낮췄으며, 오프닝·엔드게임은 4를 유지한다.

## 개발·선택과 독립 검증

이전 R13 dev457과 select153을 개발·선택 자료로 사용했다. 새 검증 자료는
완료된 공개 Lichess 대회 4개에서 395판/27,310수/348명을 확보했다.
모두 표준 초기 배치, 완료된 결과, 16수 이상, 파싱 오류 없는 대국이다.
기존 자료 전체와 같은 UCI 수열 및 신규 내부 중복을 제거했다.
출처당 최대120판을 UCI SHA256 순서로 선택했다. 성능 지표로 자료를 고르지 않았다.

검증용 대회 ID 4개는 이전 대회들과 다르다. 선수는 dev와25명, select와15명
겹치므로 선수 단위 독립이라고 주장하지 않는다. 주로 온라인 속기이며,
장시간 대국 전체를 대표하지 않는다. data-r14에 UCI, 출처 주소, 대국 헤더,
수열 해시와 분할 규칙을 포함했다. 원본 PGN 재다운로드가 달라져도 포함한
UCI 스냅샷으로 압축 실험을 재현한다.

6개 특징 조합 × 학습률 1/2/4/8 = 24후보와, 특징을 바꾸지 않은 같은
학습률의 대조군 4개를 비교했다. 초기 학습률 2/4/8에서 2가 가장 좋아,
개발 자료에서 1까지 확장했다. 이 과정과 원시 결과는 search-plan.json,
dev.csv, dev-additional.csv에 기록했다.
개발 자료의 실제 파일 크기 상위3개를 select153에서 비교하고,
가장 작은 **structure95/features7/rate1**을 고정했다.
FREEZE.json을 작성한 뒤 처음 새 heldout395를 측정했다.
보류 결과를 본 뒤 설정을 다시 조정하지 않았다.

| 묶음 | 250 payload bit | 251/mask95 bit | 새 252 bit | 250→252 실제 byte |
|---|---:|---:|---:|---:|
| dev457 | 107,323 | 107,294 | 106,751 | 13,902→13,833 |
| select153 | 35,313 | 35,310 | 35,177 | 4,587→4,573 |
| 새 heldout395 | 91,494 | 91,470 | 91,040 | 11,868→11,814 |

새 보류 자료에서 기존250 대비 payload는 454bit, 실제 파일은54byte(약0.46%)
줄었다. 중반 CDF 손실은 3.40499→3.36689bit/수다.
오프닝3.49012, 엔드게임3.03482bit/수는 그대로다.
동일 학습률의 특징 미교체 대조군은 91,246bit였다. 따라서 학습률/구조를
맞춘 상태에서도 새 특징이 206bit를 더 줄였다.
헤더·CRC·산술 코더 반올림까지 포함한 실제 파일 크기와 CDF 손실은 구분한다.

## 출처별 및 기존 자료의 한계

새 대회를 각각 별도 아카이브로 처음부터 학습해 비교한 payload 변화는
blitz1500 −29bit, rapid1300 −1bit, superblitz1700 −102bit,
superblitz_open −90bit였다. rapid1300처럼 이득이 작은 묶음은 추가 헤더로
실제 파일이 더 크다. 출처별 초기화 결과를 합쳐 전체 묶음과 동일시하면 안 된다.

기존 자료에서도 R13 sealed154는36,474→36,345bit,
R13 별도 출처285는69,198→68,751bit, R12 sealed25는8,417→8,406bit,
human4는1,929→1,925bit였다. 그러나 WCC13은4,483→4,494bit로 늘었다.
WCC 중반 손실은4.08981→4.10862bit/수로 목표3.9대에 도달하지 못했다.
따라서 새 온라인 자료 결과를 모든 수준·시간제한에서의 목표 달성으로 해석하지 않는다.
이 과거 자료들은 독립 검증 자료 수에 합산하지 않았다.

개발 자료의 짝지은 수별 추적에서는 학습률을 맞춘 대조군 대비 중반의
잡기 없는 룩 이동에서 약188.4bit, 폰 이동에서 약17.1bit를 줄였다.
폰 잡기에서는 약27.6bit 늘었다. 이번 특징의 주된 효과는 룩 예측이며,
모든 폰 이동 부류를 개선한 것은 아니다. loss-groups.csv에 부류별 내역이 있다.

## 속도

기존250, R13/mask95, 새252를 같은 O3 빌드에서 교대 측정했다.
12라운드에서 세 모델의 순서와 위치를 균형 있게 바꾸고, 각 인코드·디코드를
2회 반복했다. 선택용과 새 보류 묶음 둘 다 측정했다.
컴파일·호환성 검사·다른 벤치마크는 측정 전에 종료했다.
왕복 복원과 인코드 결정성 확인은 측정 안에서도 수행했다.
수치·원시 wall/CPU 시간·라운드별 편차는 benchmarks-r14/speed-results.md와
speed-summary.json, speed-select.csv, speed-heldout.csv에 있다.
단일 공유 환경의 결과이므로 여러 하드웨어에서의 보장으로 해석하지 않는다.

| 측정 묶음 | 비교 기준 | 인코드 처리량 변화 | 디코드 처리량 변화 |
|---|---|---:|---:|
| select153 | 250 | +5.92% | +5.78% |
| heldout395 | 250 | +5.15% | +4.49% |
| select153 | R13/mask95 | −1.35% | −1.92% |
| heldout395 | R13/mask95 | −0.78% | −3.07% |

변화율은 라운드별 처리량 비율의 중앙값이다. 새 보류 묶음에서 새 후보의
절대 처리량 중앙값은 인코드 약65,606수/초, 디코드 약65,112수/초였다.
추가 특징의 계산으로 직전 R13 속도 후보보다는 디코드가 느려졌다.
따라서 기존250 대비의 속도 이득 전부를 새 특징 덕분으로 돌리면 안 된다.

## 사용과 포맷

```bash
python3 tools/build_r14.py --out build-r14
build-r14/dmg_mid pack r14-pawn-rook sample.dmt game1.uci game2.uci
build-r14/dmg_mid unpack sample.dmt restored
```

`r14-structural`도 고정한252 기본설정95/7/1을 사용한다.
라이브러리에서는 `mid_encode_structural(games, {95,7,1})`을 호출한다.
일반 pack의 기본234는 바뀌지 않았다. 기존 파일은 헤더로 판별한다.

252는 magic `DMTF`, version1, profile252이며,
기존6byte 헤더 다음에 structure/features/rate 3byte가 들어간다.
structure는 R13 mask와 같고, features bit1은 중앙성 칸 교체, bit2는 거리 칸
교체, bit4는 잡는 수에도 적용한다. bit4가 꺼져 있으면 잡기 없는 수만 바꾼다.
유효 features는0~7, rate는1~16이다. 합치기 structure bit128에는 bit2가 필요하다.
오프닝·엔드게임 모델과 R12 나머지 파라미터는 기존250의 고정값을 쓴다.
features0/rate4/structure95는 R13/mask95와 payload가 같고 헤더만2byte 길다.
새 프로필 설정은 모두 헤더에 기록되므로 외부 모델 파일이 필요 없다.

## 검증과 재현

기존0~251 프로필의 인간23판·랜덤48판 아카이브504개는 DMT13과 byte 단위로
동일하다. 기본값 및 R10/R11/R12/R13/R14, 전체253프로필 코덱 회귀 테스트를
통과했다. 새 테스트는13개 폰·룩 의미 검증 및 색상/상하 반전,
120설정×빈 아카이브·빈 대국·인간/랜덤 기보의480건, 결정성·왕복 복원,
대조군 payload 일치, CRC, 유효 CRC를 가진 잘못된 설정·version,
모든 길이의 잘린 입력 거부를 포함한다.

```bash
python3 tools/reproduce_r14.py --out build-r14 --full --timing
```

g++ C++20과 Python 표준 라이브러리로 빌드/스냅샷 검증을 수행한다.
원본 PGN을 정제하는 prepare_r14_data.py만 python-chess가 필요하다.
reference-r13은 변경 전 구현이다. PGO/LTO/opportunity cache는 사용하지 않았다.
이전 README/benchmarks 폴더는 과거 기록이며 이번 결과는 benchmarks-r14에 있다.
