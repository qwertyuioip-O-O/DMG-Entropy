# DMT17 — 사전 학습된 중반 범주 모델

2026-10-22. 별도 학습 자료에서 배운 168개 정수 계수를 코덱에 내장했다.
일반 pack 기본234와 기존0..254 형식은 유지하며, 새 후보는 별도 `r17_prior` 도구와 D17P 연구용 형식으로 제공한다.
새439판에서 R16 strong 대비 실제 파일이0.476% 작아졌다. 세계선수권13판 중반은4.08905→3.98508bit/반수로 개선됐으나3.9 이하 목표는 아직 미달이다.

## 학습과 후보 선택

- 학습: R13 dev457판/31,585반수 중 중반14,330개 위치, 합법 후보470,656개.
- 기존 온라인 기반 분포를 오프라인 추출하고, 기존5범주/168계수의 보정값만 지도 학습했다. 엔진/신경망/추가 탐색을 쓰지 않는다.
- 목적함수: 기존 분포에 곱하는 exp 보정의 조건부 로그손실+L2 정규화. 합산 점수는 기존처럼±128, 계수도±128. 연속 최적화 후 정수로 반올림한다.
- 정규화1e-5/1e-4/1e-3의3개 테이블을 학습했다. 1e-4는200회 반복 제한에 도달했으며 이를 수렴으로 표시하지 않았다. 최종 선택한1e-5는 수렴했다.
- 각 테이블에 대해 mode0:기존0초기값, mode1:학습 초기값+온라인 갱신, mode2:학습값 고정, mode3:25% 고정 혼합, mode4:50% 고정 혼합, mode5:관측 확률에 따라 비중을 바꾸는 혼합을 비교했다.
- 혼합은 동일한 upstream 모델을 공유하며 혼합된 분포로 upstream/온라인 범주를 갱신한다. 독립 전문가 두 개의 누적 손실 보장은 주장하지 않는다.
- 선택은 R13 select153판만 사용했다. mode2/정규화1e-5가 선택용 payload35,109→34,818bit로 가장 좋았다.
- FREEZE.json을 작성한 뒤 새439판의 성능을 확인했다. 새 자료에서는 가중치/모드/정규화를 바꾸지 않았다.
- 중반 범주만 고정한다. 기존 기반 모델과 오프닝·엔드게임의 온라인 적응은 유지한다. 초기화만 적용한 mode1보다 고정 mode2가 선택용/새 전체 묶음에서 더 좋았다.
- mode2는 곧바로 기존 기반 갱신만 호출해 중반168계수의 기대값 계산과 갱신을 생략한다. 생략 전후3자료의 전체 파일이 일치한다.

## 실제 파일 비교

기준은 이전 릴리스의 `r16-strong`(layout0/rate2/cap128) 실제 DMT 파일이다. 새 D17P 형식의 헤더가1byte 더 길다는 비용도 포함했다. CDF 손실은 미들게임 위치만의 평균이고 실제 파일 크기는 모든 국면·헤더·CRC를 포함한다.

| 자료 | 기존 byte | DMT17 byte | 감소 | 기존 중반 bit/반수 | DMT17 중반 |
|---|---:|---:|---:|---:|---:|
| 새439판: 모델 고정 후 평가 | 12,812 | 12,751 | 0.476% | 3.35985 | 3.32212 |
| 세계선수권13판: 과거 회귀 자료 | 592 | 585 | 1.182% | 4.08905 | 3.98508 |
| 이전202판: 과거 회귀 자료 | 6,324 | 6,285 | 0.617% | 3.39935 | 3.34831 |
| 이전476판: 과거 회귀 자료 | 14,366 | 14,292 | 0.515% | 3.34667 | 3.30656 |
| 과거 인간4판: 회귀 자료 | 263 | 262 | 0.380% | 4.12871 | 4.06395 |

모든 위 자료에서 선택된 고정 모델이 작았으나, 세계선수권에서는 사전 학습 후에도 온라인 적응하는 mode1이3.96432bit로 mode2보다 좋았다. 이 회귀 결과를 보고 후보를 바꾸지 않았다. 어떤 방법도 이 자료에서3.9 이하에 도달하지 않았다.

## 파일을 작게 나누면

439판을 동일 순서에서 묶음 크기1/10/30/120/439로 나누고 매 파일 상태를 초기화했다. 이 분석은 같은 새 자료를 다시 나눈 특성 분석이며 추가 독립 검증이 아니다.

- 한 판씩 압축한 중반 CDF: 기존3.89928→고정 모델3.61702bit/반수. 초기값+적응 mode1은3.60994로 조금 더 좋았다.
- 동일 연구용 헤더 비교의 파일 합계22,524→22,055byte를 그대로 기존 릴리스 대비 이득이라고 부르면 안 된다.
- 기존 DMT 형식은 매 파일1byte 짧으므로 실제 기준 합계는22,085byte, 새 파일 합계는22,055byte다. 실제 이득은30byte(약0.136%)다. 작은 파일에서는 프레이밍 비용이 예측 개선을 대부분 상쇄한다.
- 439판 한 파일은 실제12,812→12,751byte다. 블록별 나머지 결과와 복원 검사는 blocks.csv에 있다.

## 속도

모든 빌드·검사 종료 후, 같은 실행 파일의 mode0과 mode2를6회 번갈아 실행했다. 매 프로세스에서 예열 복원 후 인코딩3회·디코딩3회, 결과 검증을 포함한다. 계수 파일 로딩은 측정 밖이다.
mode0 payload는 실제 R16 strong과 비트 단위로 같지만 도구의 래퍼/메모리 배치는 다르므로 이전 실행 파일 자체에 대한 직접 속도 비교라고 주장하지 않는다.

| 자료 | 인코딩 처리량 변화 중앙값 | 디코딩 처리량 변화 중앙값 | 고정 모델 인코딩/디코딩 반수/초 |
|---|---:|---:|---:|
| new | +2.50% | +5.73% | 64,415 / 65,827 |
| r16confirm | +1.38% | +0.96% | 64,570 / 66,018 |

새439판은 인코딩6/6·디코딩5/6회 빨랐고, 이전202판은 각각4/6회 빨랐다. 공유 환경의 흔들림이 있으며 보편적인 속도 우위나 통계적 유의성을 확정하지 않는다. 측정 원자료/짝별 변화는 speed.csv와 summary.json에 있다.

## 새 자료와 누수 제한

새 평가 자료는 이미 종료된 Lichess 대회4개(xu1AeNte/cvpXbGYg/gf4Wbxzz/UFJWzIev)의439판/29,936반수/424명이다. 3·5·10분 계열과 등급 제한 대회를 포함한다. 표준 초기 배치, 완료 결과,16반수 이상, 파싱 오류 없는 기보만 사용하고 이전 모든 전체 UCI 수열과 신규 내부 중복을 제거했다. 출처당 최대120판을 UCI SHA256 순서로 선정했다.
대회 출처는 학습/선택/과거 평가와 다르지만 선수는 dev36명/select9명이 겹쳐 선수 단위 독립 검증은 아니다. 공개 속기 자료로서 모든 수준의 체스를 대표하지 않는다. 원래 API 주소·기보 헤더·해시·완료 대회 여부와 고정 UCI는 data-r17에 있다. PGN API의 이후 응답이 달라도 포함된 UCI로 재현한다.
학습 예제의 기존 온라인 분포는 0초기값으로 추출한 경로다. 새 prior를 넣었을 때 바뀌는 모든 upstream 적응 경로를 미분한 학습은 아니며, 실제 코덱 평가로 이 차이를 검증했다.

## 형식과 검증

- 168×int16=336byte 모델은 코덱 상수이며 매 아카이브에 저장하지 않는다. 디코더에 동일 모델이 필요하다. 모델을 파일마다 별도 전송하면 그 비용을 추가해야 한다.
- D17P v1 헤더에는 모드와 계수 테이블의 CRC32 식별값을 넣고 전체 파일 CRC를 검사한다. 잘못된 테이블은 거절한다. CRC는 보안용 해시가 아니다.
- 기존 프로필을 재사용하지 않았다. 기존 CLI는 기존 형식을, 새 연구용 도구는 D17P를 처리한다. 일반 pack 기본234를 승격하지 않았다.
- 기존 src/include15개 파일이 R16과 완전히 동일함을 기록했다. R16의508개 호환 검사를 이번 최종 빌드에서 새로 반복했다고 주장하지 않는다.
- 새 도구의548개 검사: 빈 묶음·빈 판·한 수·인간 기보,0..5모드 복원, CRC 변경, 잘린 입력, 다른 계수 거절,0prior 항등성, 기존 R16 payload 항등성.
- 최종 builtin과 파일 계수의 전체 파일 일치, 실제 pack/unpack UCI 일치, 최종 새439판/세계선수권/인간 자료6모드 표의 원래 실험 결과와 완전 일치를 확인했다.
- 혼합 경로의 전체 context 복사를336byte 계수만 잠시 교체하는 방식으로 바꿨다. mid_step은 context를 읽기만 하며 결과가 동일함을 최종 표로 확인했다.
- 최종 코드·계수·환경·동결 기록, 선택/새 평가/과거 회귀/출처별/블록/속도 원자료를 함께 보관했다.

## 실행

Python3와 g++ C++20으로 빌드한다. 학습 재현에만 NumPy/SciPy, PGN 재준비에만 python-chess가 추가로 필요하다.

```bash
python3 tools/build/build_r17.py --out build-r17
build-r17/r17_prior pack data-r17/heldout.uci-bundle builtin 2 result.d17
build-r17/r17_prior unpack result.d17 builtin decoded.uci-bundle
build-r17/r17_prior test benchmarks-r4/human4.uci-bundle builtin
python3 tools/reproduction/reproduce_r17.py --out build-r17 --blocks --timing
# 선택 사항: 기존 dev만 다시 추출해 학습
python3 tools/reproduction/reproduce_r17.py --out build-r17 --retrain
```

재현 스크립트 자체의 전체 재실행은 하지 않았으며, 최종 빌드/표/검사/블록/속도는 같은 명령을 순서대로 직접 실행했다. 학습은 SciPy 버전에 따라 마지막 반올림이 달라질 수 있어 frozen 모델과 training.json의 해시를 기준으로 비교한다.

## 판단

사전 학습을 도입하는 방향은 실제로 유효했다. 이번 후보는 중반 범주 모델을 고정해 압축 이득과 갱신 연산 생략을 함께 얻었다. 다만 전체 파일 이득은0.5% 안팎이며 획기적인 수준이라고 부르지 않는다. 세계선수권3.9 목표도 남아 있다. 고정 모델을 연구 옵션으로 제공하고 추가 독립 출처/환경 검증 전 기본값은 유지한다.
