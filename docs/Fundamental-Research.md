# DMG-Entropy의 근본적 개선을 위한 연구 보고서

작성일: 2026-10-20. 분석 대상: 첨부 DMG-Entropy-Cpp-v0.7.zip 및 DMG-Entropy-Results-v0.7.md.

## 1. 권고와 연구 범위

**최우선 연구는 ‘관계 기반 후보 표현 + 실제 선택집합에 대한 온라인 조건부 학습’이다.** 현재 좌표·기회 보정 사전의 키를 더 잘 고르는 수준에서 벗어나, 포지션이 달라도 같은 의사결정 구조가 같은 파라미터를 갱신하게 만드는 설계다. 얕고 결정론적인 탐색이 만드는 반사실적 손실 분포를 두 번째 정보원으로 붙인다. 가장 과감한 병행 연구는 한 반수 대신 여러 반수를 생성하는 짧은 프로그램을 부호화하는 것이다.

산술 부호화를 먼저 교체할 이유는 약하다. 실제 첨부 표본에서 부호기 자체의 남는 손실은 전체 약 0.63 비트였다. 3.9 또는 3.5 bit/반수를 달성할지는 독립 데이터 실험 전에는 판단할 수 없다.

이 보고서는 기존 소스의 검토와 작은 진단 실험을 수행했다. 아래 9 개 대안의 압축 성능을 구현·입증한 보고서는 아니다. ‘새로운 조합’과 ‘연구 가설’은 DMG에 대한 제안이라는 뜻이며, 세계 최초나 특허상 신규성을 주장하지 않는다. 사전 학습 모델, 외부 가중치, 외부 오프닝북, 외부 테이블베이스는 사용하지 않는다.

## 2. 실제 구현에서 확인한 사실

### 2.1 후보는 항상 완전한 합법수 집합이 아니다

`src/entropy.cpp`의 `candidates()`는 `pseudo_destinations()`로 후보를 생성한다. v6/v7 의 기본 경로는 `EntropyCheckSignalLight`를 쓰며, `remove_illegal_during_check()`는 현재 체크일 때만 `apply_checked()`로 걸러낸다. 따라서 체크가 아닌 포지션에서는 핀 때문에 움직일 수 없는 수, 움직인 뒤 왕이 노출되는 수 등이 확률 질량을 차지할 수 있다. 인코더는 실제 입력 수를 검증하고 디코더도 복원 수를 검증하므로, 이것은 정상 기보의 무손실성 오류가 아니라 압축상의 낭비다.

기존 모델 경로를 그대로 유지한 상태에서, 매 포지션의 합법 후보 확률 합을 Z_t라 하면 조건부 재정규화의 이익은 정확히 `-log2 Z_t`다. `q_legal(m)=q(m)/Z_t`이기 때문이다. 이는 모델 업데이트까지 바꾼 새 코덱의 성능을 예측하는 공식은 아니다.

### 2.2 모델 전환은 이미 구현돼 있다

`v7_advance()`는 posterior 갱신 후 switching/opportunity/selective 모드에서 약 1/32 질량을 균등 prior 쪽으로 돌린다. **따라서 ‘fixed-share를 추가하자’는 제안은 중복이다.** 더 나아갈 부분은 전환률의 불확실성, 문맥별 전문성, 그리고 재시작 정책이다.

`V7Context ctx`는 각 게임 안에서 생성된다. 정확한 포지션 사전과 패턴 사전은 아카이브 전체에 공유되지만, 전문가 posterior와 일부 유형 통계는 게임마다 초기화된다. 이 상태 범위의 차이가 모델 경쟁의 비용을 만든다.

### 2.3 기회 보정은 현재 모델의 예측오차 학습과 다르다

`observe_opportunity()`의 expected는 현재 보정 모델이 아니라 원래 baseline의 확률에서 계산된다. `v7_opportunity()`는 actual/expected 비율을 prior로 완화하고 약 [1/3, 3]으로 제한해 baseline에 곱한다. 이는 유용한 보정이나, 여러 겹치는 특징을 실제 후보 경쟁 아래에서 동시에 최적화하는 조건부 우도 학습은 아니다.

### 2.4 추가로 수행한 진단

첨부된 `examples/heldout/*.uci` 23 개를 파일명 순서로 처리했다. 이 자료는 이미 반복 사용된 **개발 표본**이다. 이름에 heldout이 있어도 독립 평가로 취급하지 않는다. g++ C++20, -O2 로 컴파일했다. 기존 DMG7 테스트가 통과했고 원본 opportunity-square의 7,085 payload bit, 923 bytes를 재현했다. 처리 속도에 대한 새 주장은 하지 않는다.

## 3. 근본적인 약점 다섯 가지

1. **공유 상태에서 확실히 배제할 수 있는 후보를 남겨 둔다.** 완전 합법수화로 바로잡을 수 있지만, 이번 표본의 이익은 약 0.030 bit/반수여서 이것만으로 목표에 도달하지 않는다.
2. **표현이 표면적이며 선택집합에 대한 조건화가 약하다.** 같은 좌표의 나이트 이동도 전개·위험 회피·포크 생성이라는 다른 이유를 가진다. 반대로 서로 다른 좌표의 이동이 같은 관계적 이유로 선택될 수 있다.
3. **반수 단위 예측과 짧은 이력이 지속되는 의도를 충분히 표현하지 않는다.** 현재 판에 남지 않은 이전 자기 착수와 추격·왕복 이력도 사람의 다음 선택에 영향을 줄 수 있다.
4. **전문가 선택과 정보 결합을 같은 문제로 취급한다.** 평균은 좋은 전문가를 고르는 데 유용하지만, 서로 다른 증거를 공동으로 반영하는 데 한계가 있다. 고정 share와 게임별 재초기화에도 별도의 비용이 있다.
5. **배치를 주로 긴 순차 스트림으로만 사용한다.** 정확한 상태 재등장은 활용하지만, 문맥별 출발열·여러 수 생성 규칙·수순의 순서 동치류를 직접 저장하는 표현은 없다.

## 4. 정보이론의 경계와 목표의 크기

기초식은 `L ≈ Σ -log2 q_t(m_t) + 부호기·양자화 차이 + 보조정보 + 컨테이너`다. 참분포p에 대한 기대 교차엔트로피는 `H(p)+D_KL(p||q)`다. 4.124 는 참 엔트로피의 추정치가 아니라 작은 개발 표본에서 나온 실제 길이다.

한 반수씩 부호화해도 전체 이력을 조건으로 쓸 수 있다면 연쇄법칙으로 임의의 수순 분포를 표현한다. `P(m1..mk)=Π P(mi|m1..m(i-1))`이므로, 여러 반수를 묶었다는 사실 자체는 절감이 아니다. 문법·잠재상태·배치 표현의 가치는 현재의 작은 모델로 다루기 어려운 의존관계를 효율적으로 학습하는 데 있다.

같은 확률분포라면 ANS 교체나 좌표 변환만으로 정보가 몇십 퍼센트 사라지지 않는다. ANS는 다른 구현상 장점을 가진 엔트로피 부호기이며 확률을 고정한 채 엔트로피를 돌파하지 않는다.[S1, S2]

| payload 목표 | 4.1240 에서 필요한 감소 | payload 감소율 | 실제 선택에 부여한 기하평균 확률의 필요 배율 |
|---|---:|---:|---:|
| 3.9 bit/반수 | 약 0.2240 bit/반수 | 약 5.43% | 약 1.168 배 |
| 3.5 bit/반수 | 약 0.6240 bit/반수 | 약 15.13% | 약 1.541 배 |

배율은 `2^(이전 평균길이−새 평균길이)`로 계산한 목표의 다른 표현이지, 달성 전망이 아니다. 모든 수의 확률을 동일하게 올릴 필요도 없다. 예를 들어 전체 절반의 수에서 평균 0.448 bit를 줄이고 나머지에서 악화하지 않으면 전체 0.224 bit가 줄어든다. 실패한 수에서의 증가분도 포함해야 한다.

원본 총길이는 `923×8/1718 = 4.2980 bit/반수`다. payload 7,085 bit와의 차는 299 bit, 약 0.1740 bit/반수다. 같은 차 299 bit가 유지된다고 가정하면 **총길이**3.9 에 필요한 payload는 개략 3.726 이하, 총길이 3.5 에는 개략 3.326 이하다. 실제 판정은 byte 반올림과 varint 길이 변화까지 포함한 파일bytes로 한다.

짧은 단일 게임은 고정 헤더의 비중이 크다. 대형 아카이브의 3.5 와 짧은 한 게임을 독립 저장하는 총길이 3.5 는 다른 목표다.

한편 매번 합법수를 균등하게 고르는 생성과정에서, 고정 게임길이의 기대 조건부 길이 기준은 `E[Σ log2 |Legal(Pt)|]`이다. 종국에서 종료하는 생성기라면 정지 규칙도 포함한다. 유한 표본에서 우연히 더 짧아질 수는 있지만, 인간용 모델로 이 균등 생성과정의 기대길이를 지속적으로 낮출 수는 없다.

## 6. 안 1: 관계 구조에 대한 온라인 조건부 선택 모델

**발상·차이.** 출발·도착 좌표 대신 착수가 바꾸는 관계를 공유한다. 예를 들어 이동 전 공격받던 자기 기물이 이동 후 위험에서 벗어나는지, 상대 고가치 기물에 공격을 만드는지, 수비 기물을 제거하는지, 왕을 향한 선의 차단물을 치우는지다. 새 보너스의 수치를 사람이 설정하는 대신, 선택된 수와 모든 경쟁 후보 사이의 차이로 기여를 학습한다.

**압축·복원.** 기물을 정점으로, 공격·수비·차단·핀·왕과의 선상 관계를 간선으로 표현한다. 후보m의 전후 차에서 고정 규격의 작은 관계 특징φ(P,m,H)를 추출한다. 일반 그래프 동형성 판정은 하지 않는다. 색을 자기 진영 기준으로 바꾸되 폰 방향과 캐슬링 비대칭을 보존한다. 원시 특징과 제한된 두 특징 조합, 일부 세 기물 관계만 허용한다.

이상적인 실수 식은 `q(m) ∝ b(m) exp(θ·φ(P,m,H))`다. b는 완전 합법수 baseline이다. 실제 수y를 복원한 뒤 다음과 같이 갱신한다.

`θ ← shrink(θ) + η[φ(P,y,H) − Σ_m q(m)φ(P,m,H)]`

모든 계수는 0 에서 시작하고 현재 아카이브의 이미 복원한 부분만 이용한다. 실코덱에서는 관계 전문가 자신의 양자화된 갱신 전 분포로 기대값을 계산한다. 관계 전문가만 쓰면 이 분포가 실제 부호화 분포다. 여러 전문가를 혼합할 때도 기본 전문가들은 각각 자신의 분포로 학습한다. 최종 혼합 손실을 직접 미분하려면 관계 전문가의 posterior 책임도까지 곱해야 하므로 두 갱신법을 섞지 않는다. 양쪽은 동일한 정수 근사를 실행한다.

**상태·메모리·계산.** 약 32 기물의 관계 그래프, 후보별 최대F개 희소 특징, 고정용량 계수표다. 예컨대 2^18 개의int32 계수 본체는 1 MiB다. 키·최적화 상태·후보 특징·탐색표 메모리는 별도다. 단순 시제품은 후보마다 보드를 복사해 공격 관계를 다시 계산해도 된다. 계수 계산은O(MF), 관계 생성 비용은 추가된다.

**줄어드는 이유.** 좌표가 재등장하지 않아도 같은 관계에서 학습을 공유한다. v7 expected가 고정 baseline의 주변 기대값인 데 비해, 이 갱신은 현재q의 조건부 기대값을 사용해 겹친 특징과 경쟁 후보에 공동으로 기여를 배분한다. 목적함수가 다음 수의 로그손실, 곧 순차 부호길이다.

**악화 조건.** 특징 과다, 희귀 교차, 상관 중복, 혼재된 기력·시간제어, 초반 과신이다. 강한 축소와 적은 특징부터 시작한다. 이 관계들이 실제 인간의 선택을 설명한다는 보장은 없다.

**C++20 시제품.** (a)합법화v7, (b)새 특징을 v7 식 A/E로 각각 보정, (c)같은 특징을 위 식으로 공동 학습한다. 새 특징의 가치와 학습법의 가치를 분리한다. 탐색·잠재계획 없이 사전 고정한 20～40 개 관계 특징으로 시작한다. top-1 정확도가 아니라 양자화된 로그손실과 실제 파일길이를 비교한다.

**기술 분류.** 조건부 log-linear 선택모형과 온라인 로그손실 최적화는 알려진 기술이다. DMG의 관계 차분에 적용하는 것은 새로운 조합이며 압축 효과는 연구 가설이다. 신경망·사전학습이 필요하지 않다.

**기각 기준.** 다른 오프닝·기력의 독립 집합에서(c)가(a)(b)보다 재현 가능한 이익을 보이지 않으면, 적어도 해당 특징군과 용량의 가설은 기각한다.23 게임의 개선만으로 채택하지 않는다.

## 7. 안 2: 유한 탐색으로 반사실적인 손실 분포 구성

**발상·차이.** ‘포획이므로 가점’ 대신 ‘이 수 뒤에 상대가 응답하면 무엇을 잃는가’를 양쪽이 계산한다. 얕은 minimax·정지탐색은 정적 전술 가점과 다른 정보다. 최선수를 맞히면 고정 접두부를 주는 방식은 아니다.

**압축·복원.** 모든 합법 root 후보에 상대 응답과 제한된 후속 탐색을 수행한다. 고정 깊이·노드 예산·정수 평가·안정된 순서를 사용한다. root 후보 전체의 점수를 반드시 얻는다. 예산이 끝나면 모든 후보를 평가한 공통 깊이 결과를 사용하고, 일부만 깊게 탐색한 결과로 비교하지 않는다.

`r(m)=max_a V(a)−V(m)`를 구간화하고 순위·1 위와의 gap·비슷한 후보 개수·실제 깊이를 정수LUT 확률에 넣는다. `q_search(m) ∝ exp2(−r(m)/τ)`는 시작 가설일 뿐이다. τ나 gap 교정은 현재 아카이브에서 순차적으로 배우며, 모든 합법수에 양의 확률을 남긴다. 외부 신경망 평가·book·tablebase는 사용하지 않는다.

**상태·메모리·계산.** 얕은αβ, 제한 정지탐색, 고정용량TT가 필요하다. 예컨대 1k/4k/16k노드/반수는 실험 조건이며 달성 성능이 아니다. 압축과 복원 모두O(B) 탐색노드가 든다. 최초 시제품은 root별 동일한 별도 예산으로 단순화할 수 있다.

**줄어드는 이유.** 공유 계산으로 정적 특징이 분별하지 못하는 후보들의 상대 확률을 개선한다. 계산량 자체가 정보를 없애는 것은 아니다. 인간의 실제 선택에q가 가까워져야 줄어든다.

**악화 조건.** 인간의 실수·시간압박·주관적 계획, 탐색 수평선 효과다. 강한 엔진과 인간 착수 예측은 다르다. Maia 연구 역시 이 차이를 다루지만, 여기서는 Maia 가중치를 쓰지 않는다.[S3]

**C++20 시제품.** 기물가치와 간단한 고정 평가로 깊이 1/2, 제한 정지탐색을 비교한다. 순위만·gap만·둘 모두를 분리한다. 탐색 없는 안 1 과 같은 CPU시간을 더 풍부한 관계 생성에 쓴 조건도 비교한다.1 위 일치율이 아닌 로그손실과 절약bit당 시간으로 평가한다.

**기술 분류.** 결정론적인 체스 프로그램을 이용한 압축은 Althöfer의 1990/1991 년 연구 등 선례가 있다.[S4] 새 압축이론이 아니다. 외부학습 없는 제한 탐색·인간 선택의 순차 교정·관계모델 통합이 DMG용 조합이다.

**기각 기준.** 독립 인간 집합에서 추가 탐색 이익이 0 이하이거나 허용CPU 예산에서 유효한 성능·시간 절충점을 만들지 못하면 해당 탐색·교정군을 중단한다. 최상위 정확도만 오르고 실수의 긴 부호 때문에 로그손실이 악화해도 실패다.

## 8. 안 3: 교대 차례 뒤의 지속 계획을 잠재상태로 유지

**발상·차이.** 인간은 직전 상대수뿐 아니라 2 반수·4 반수 전에 시작한 자기 작업을 계속한다. 기물 궤적과 목표를 유지해 개별 이동 방향의 빈도에서 ‘계속 진행하는 행동’으로 모델을 바꾼다.

**압축·복원.** 백흑 각각 적은 잠재상태z를 가진다. 예시는IDLE, 방금 움직인 자기 기물의 연속 이동, 특정 상대 기물 추격, 특정 영역으로의 이동이다. 기물ID는 초기 기물에 배정하고 이동·승격 뒤에도 실체를 추적한다. 초기에는 8～32 상태로 제한한다.

`q_t(m)=Σ_z π_t(z)P(m|P_t,z)`로 예측하고, 수를 복원하면 Bayes 갱신해 다음 자기 차례까지 보존한다. 전이는 현재 판과 이미 복원한 이력에만 의존한다. 목표 기물이 잡히면 해당 상태의 질량을IDLE 등으로 결정론적으로 옮긴다. z를 따로 보내지 않고 forward 계산으로 주변화한다.

**상태·메모리·계산.** 양쪽의π, 목표ID·영역, 작은 전이모형과 배출통계다. O(ZM+Z²), 희소 전이면O(ZM+ZE)다. 상태 생성·제거·정규화 순서까지 고정한다.

**줄어드는 이유.** 현재 판만으로는 표현하기 어려운 이력의 조건부 정보를 이용한다. 잠재변수 자체가 이익을 만들지는 않으며 계획이 다음 자기 수를 예측해야 한다.

**악화 조건.** 잦은 계획변경, 강제응답, 같은 궤적의 다른 목표, 상태 과다에 따른 희석이다. ‘같은 기물을 다시 움직이기’라는 고정 가점만으로 대체하면 안 된다.

**C++20 시제품.** 같은 특징으로(a)판만, (b)직전 반수, (c)직전 자기수, (d)잠재계획을 비교한다. 분석에서 자기 이전 이력을 섞었을 때 이익이 사라지는지도 확인한다. 이는 진단이며 실제 입력 기보를 바꾸는 것이 아니다.

**기술 분류.** HMM·유한상태원·옵션모형은 기존 기술이다. 외부학습 없이 체스의 지속계획을 온라인 주변화하는 조합의 압축 가치는 연구 가설이다.

**기각 기준.** 간단한t−2 이력 대조보다 낫지 않으면 복잡한 잠재상태화를 채택하지 않는다. 판만 쓰는 대조에 이기는 것으로 충분하지 않다.

## 9. 안 4: 문맥별 전문성과 전환 구조 자체를 혼합

**발상·차이.** 매 반수 1/32 를 되돌리는 것만으로는, 같은 종류의 국면이 다시 왔을 때 과거 전문성을 즉시 재사용하기 어렵다. 체크·낮은 기물수·정확사전의 재방문 여부·후보수처럼 decoder가 아는 작은 문맥마다 전문성을 유지한다. 기존 fixed-share의 이름만 바꾸는 제안이 아니다.

**압축·복원.** 사전 고정한 깊이 2～4 의 문맥목에서 국소 전문가 혼합과 더 세밀한 분할을 주변화한다. 각 절점의 증거를 보존하고 부모의 거친 모형과 자식의 세밀한 모형이 경쟁한다. 기본 전문가 모두는 실제로 복원된 동일한 수를 관측해 갱신한다. 선택된 expert에 따라 기본 학습이 달라지는 방식은 처음에는 피한다.

상위에서는 archive-static Bayes, 기존 fixed-share, 여러 share율, 게임경계 reset/지속이라는 **다른 경로prior**를 Bayes 혼합한다. 고정 크기share율 grid면 시제품이 작다. 사후 최적α를 무료로 선택하지 않으며 상위 혼합 비용도 부호길이에 들어간다.

**상태·메모리·계산.** K전문가·깊이D·share후보J일 때 기본예측을 공유하면 대략O(KM+JKD), 상태는O(JK·절점수)다. 최대 절점수를 제한한다. 원래 CTW는 이진 tree source의 이론이다. 판면 문맥목 변형에 원래의 중복도 보장을 그대로 적용하지 않는다.[S5]

**줄어드는 이유.** 전문성이 시간순으로 바뀌는 것뿐 아니라 문맥이 되돌아올 때 회복되는 현상을 이용한다. 세분화의 비용도 지불한다. 전문가 경로에prior를 부여하는 switching code는 알려진 이론이다.[S6]

이상적인 static Bayes 혼합은 동일한K전문가를 archive 전체에서 추적할 때 `L_mix ≤ min_j L_j+log2 K`다. 게임마다 초기화하면 비교대상은 게임별 최적expert의 길이 합이고 추가 상한은 `G log2 K`다. K=8,G=23,N=1718 이면 약 0.04016 bit/반수다. 실손실의 측정값이 아닌 이상적 상한이다.

고정share α=1/32 에서 특정expert에 계속 머무는 경로를 비교하는 보수적 상한에도 대략 `(N−1)(−log2(31/32))`가 들어간다. 반수당 약 0.04580 bit의 상한항이며 반드시 그만큼 손해라는 뜻은 아니다. 정수 바닥·반올림·reset은 이상 보장과 별도로 평가한다.[S6]

**악화 조건.** 희귀 문맥, 과한 분할, αgrid의 초기 적응비, 실제 전문성이 없는 자료다. 매 순간 정답에 가장 높은 확률을 준 expert를 무료로 선택하는oracle와의 차는 실현 가능한 이득이 아니다.

**C++20 시제품.** 동일 8 전문가로(a)기존, (b)archive-static Bayes, (c)game-reset Bayes, (d)αgrid, (e)얕은 문맥목을 비교한다. 분석용 고정밀 참조와 정수판의 차도 기록한다. 현재약 0.014 bit/반수 차가 이 구조로 설명되는지 먼저 본다.

**기술 분류.** CTW·expert HMM·전환율 혼합은 기존 기술이다. 판면 문맥과 게임경계 계층화가 새 조합이다.

**기각 기준.** archive-static Bayes와 기존share를 상위 혼합한 작은 대조보다 문맥목이 독립 자료에서 낫지 않으면 문맥목을 제거한다.

## 10. 안 5: 전문가의 상대 오즈를 공동 교정

**발상·차이.** 산술평균은 어느 expert를 믿을지에 적합하다. 독립에 가까운 증거가 같은 후보를 지지하면 증거를 곱해 강화하는 편이 좋을 수 있다. v7 도 baseline에A/E비를 곱하므로 ‘확률을 곱하자’만으로는 새 제안이 아니다. 여러 expert의 상대 증거를 함께 학습하고 상관·과신을 교정하는 것이 차이다.

**압축·복원.** baseline b와 expert q_j에서 `r_j(m)=log(q_j(m)/b(m))`를 얻고 `q(m) ∝ b(m)exp(Σ β_j r_j(m))`로 만든다.0 확률은 쓰지 않는다. β=0 에서 시작해 `β_j += η[r_j(y)−Σ_m q(m)r_j(m)]−shrinkage`를 정수 근사로 갱신한다. β와r의 범위를 제한하고 음수β 허용 여부도 실험으로 분리한다.

**상태·메모리·계산.** 기존K분포, K개 또는 소수문맥별β, log/exp LUT다. O(KM)이며 추가계수가 적다. 분석용 실수log/exp를 그대로 이식가능한 코덱이라고 주장하지 않는다.

**줄어드는 이유.** 재방문과 위험회피 등 다른 정보가 서로 보완할 수 있다. 동일 후보에q1=q2=0.2 여도 나머지 후보 배분이 다르면 정규화된 곱은 0.2 를 넘을 수 있지만 산술평균은 각expert의 그 후보 확률 최댓값을 넘지 않는다. 상관된 증거를 중복 계산하면 반대로 과신하므로 공동 교정이 필요하다. 이진 logistic mixing의 선례는 있지만, 가변 합법수의 다값 공간에서 개선이 보장되지는 않는다.[S7]

**악화 조건.** 강한 상관, 모든expert가 같은 실수를 놓치는 경우, 초반학습, 지나치게 뾰족한 곱이다. 균등분포로의escape나 소수 온도후보를 비교하고 긴 부호의 꼬리를 측정한다.

**C++20 시제품.** 새로운 판면 특징 없이 같은 expert열에 평균·고정곱·학습곱을 적용한다. 안 1 과 통합할 때는 안 1 만/안 5 만/둘모두를 따로 측정해 중복이득을 확인한다.

**기술 분류.** log-linear pooling·product of experts·logistic context mixing은 기존 기술이다. 다값 후보의baseline 상대잔차로DMG에 넣는 것은 새 조합이다.

**기각 기준.** 같은 기존expert에서 학습곱이 평균을 이기지 못하면 특징을 추가해 효과를 가리지 않는다. 적어도 그 expert군에 대한 결합 가설은 기각한다.

## 11. 안 6: 여러 반수를 생성하는 작은 프로그램을 부호화 ★

**발상·차이.** 기보를 `수, 수, 수` 대신 `짧은 절차, 예외, 짧은 절차`로 나타낸다. 예를 들어 특정 교환 지점에서 최소 가치 합법 공격자로 잡고 상대도 같은 규칙으로 재포획하는 2～6 반수의 수순, 명시적으로 정한 규칙에 따른 체크 회피와 추격, 이미 복원된 게임의 연속 수순 참조다. 이것은 한 수의 예측 성공 접두부가 아니라 실제로 복수의 반수를 출력하는 가변 길이 토큰이다.

**압축·복원.** 현재 상태에서 같은 규칙으로 생성 가능한 유한한 토큰 집합을 양쪽이 만든다. `RAW(m)`은 모든 합법수를 지원하고, `PROGRAM(script_id, anchor_rank, length)`와 `COPY(previous_game, offset, length)`가 긴 수순을 출력한다. 모든 필수 파라미터와 후보 식별자는 토큰 확률 또는 명시 필드로 비용을 낸다. 여러 토큰이 같은 수순을 만들면 중복 제거와 순서를 고정한다.

프로그램의 전개 결과는 현재 보드에서 결정론적으로 계산되며, 길이 전체를 시뮬레이션해 합법인 토큰만 제시한다. 재포획이 실제로 ‘강제’인지와 무관하게 토큰을 사용하려면 실제 입력과 **정확히** 같아야 한다. 맞지 않으면 RAW를 선택한다. 프로그램 성공 확률은 1 로 가정하지 않는다.

경계에서 `P(RAW(m))=(1−ρ)q_base(m)`과 `P(PROGRAM_i)=ρ w_i/Σw`를 사용하면 선택·실패 비용이 분포에 포함된다. 프로그램 후보가 없으면 ρ=0. ρ도 과거만으로 정한다. 길이를 별도 전달하거나 토큰 ID에 포함한다. 게임 길이는 별도로 알고 있어야 하며 끝을 넘기는 프로그램은 후보에서 제거한다.

**필요 상태·비용.** 고정 script 인터프리터, 과거에 복원된 수순의 제한된 참조 창, 최대 길이 k, 최대 토큰 C. 예를 들어 C≤32, k≤8 로 시작한다. 후보 생성은 대략 O(Ck·착수검증비용). encoder는 현재 게임 또는 작은 블록을 버퍼링할 수 있고 decoder는 토큰을 확장한다. COPY용 과거 기보 메모리는 고정 용량으로 제한한다.

**정보이론적 이유.** 같은 의미 있는 연속 동작의 확률을 독립적인 반수 모델보다 잘 모형화할 수 있다. `L(token, parameters)`가 해당 수순의 RAW 비용 합보다 작은 경우만 이익이다. 길이 k 자체로 절감되는 것은 없다. 알려진 문법 압축과 LZ 계열 원리를 체스 상태에 종속되는 프로그램으로 확장하는 설계다. 문법 압축의 세계적 신규성을 주장하지 않는다.[S8]

**악화 조건.** 짧고 드문 패턴, 많은 anchor 선택지, 낮은 프로그램 이용률, RAW 쪽에 계속 내는 `(1−ρ)` 비용. 임의 게임에서 COPY 대상이나 script가 거의 안 맞으면 악화한다. encoder가 성공하는 프로그램만 보고 토큰 확률을 공짜로 높여서는 안 된다.

**C++20 최소 검증.** 먼저 script 3 개와 RAW만 구현한다. 실제 수순과 일치하는 모든 token edge를 구해, `DP[t]=min_token(cost_t(token)+DP[t+len])`로 최단 표현을 고른다. 이 DP가 유효하려면 token 후보·확률·기본모델 상태가 선택한 parse가 아니라 **복원된 원시 착수 prefix**에만 의존해야 한다. 선택된 토큰 빈도로 모델을 갱신하면 경로 의존성이 생기므로 단순 DP가 틀린다. 첫 구현은 블록 내 token 통계를 고정하고 블록 후 원시 수순으로 갱신하면 쉽다. 비교군도 같은 블록 고정 정책을 사용한다.

decoder는 토큰이 낸 각 수마다 원시 착수 모델·사전·이력 갱신을 같은 순서로 실행한다. 향후에는 여러 parse를 forward 계산으로 주변화해 한 수씩 산술 부호화할 수도 있지만, 첫 실험은 명시 토큰 경로가 더 검증하기 쉽다.

**기술 분류.** 문법/LZ/유한상태 transducer는 기존 기술. 체스의 합법성으로 제한된 매개변수 프로그램과 RAW를 결합하는 것은 새로운 조합·연구 가설.

**기각.** 토큰 ID·길이·참조·RAW 세금·종료까지 포함한 전체 길이가 RAW 대조군보다 줄지 않으면 기각한다. 반복 기보에서만 이기면 일반 기보 혁신이라고 채택하지 않고 중복 아카이브 전용 기능으로 한정한다.

## 12. 안 7: 아카이브를 상태 그래프와 문맥별 출발열로 재구성 ★

**발상·차이.** 정확한 포지션 사전을 다음 수의 확률에 보너스를 주는 용도로만 쓰지 않는다. 전체 배치를 먼저 읽고, 관측된 상태와 전이로 이루어진 유향 그래프를 만든 뒤 **각 상태에서 출발한 수들의 열을 모아서** 부호화한다. 게임은 그래프를 따라가는 경로이며, 출력 순서는 각 노드의 출발열을 순서대로 소비해서 복원한다. 사이클이 가능하므로 DAG라고 가정하지 않는다.

**압축·복원.** 모든 게임이 표준 초기 상태에서 시작한다면 root는 이미 공유된다. 보드·차례·캐슬링권·앙파상 상태의 완전 키로 노드를 합친다. root에서 결정론적 BFS를 수행한다. 각 노드에서 (a) 관측된 outgoing degree, (b) 전체 합법수 중 관측된 수의 정렬된 부분집합, (c) 각 outgoing move의 관측 횟수와 실제 출발 순서열을 기록한다.

노드에서 선택된 수를 실제 적용하면 목적 상태를 계산할 수 있다. 이미 발견된 완전 키이면 합치고 아니면 BFS 큐에 넣는다. 따라서 매 노드의 64 칸 보드나 매 edge의 목적 node ID를 무조건 저장할 필요는 없다. degree 0 인 종단 노드도 처리한다. 부분집합은 합법수 번호의 gap 또는 조합 부호로 저장한다.

게임 길이·게임 순서를 헤더로 전달한다. decoder는 topology와 노드별 출발열을 먼저 복원한 뒤, 첫 게임의 root에서 출발열의 다음 move를 하나 소비하고 목적 상태로 이동한다. 길이를 채우면 다음 게임에서 root로 돌아간다. 모든 출발열과 길이가 맞게 소모됐는지 검증한다. 같은 노드에서 출발한 수가 시간순으로 어떤 순서였는지도 출발열에 보존하므로 게임 순서와 수순이 정확히 복원된다.

현재 코드의 합법수 의미는 보드·차례·권리로 정해지는 착수 가능성이다. 50/75 수 규칙이나 반복에 따른 자동 종료까지 미래 동작을 제한하도록 의미를 바꾸면 해당 이력·카운터도 상태에 넣거나, 그래프는 착수 합법성만 담당하고 종료 검증은 원래 경로를 재생하며 별도로 해야 한다.

**필요 상태·비용.** 전체 N반수의 전이 수집, V상태/E관측edge의 그래프, 노드별 큐. 평균 해시 접근 기준 O(N+E·합법수생성), 메모리 O(V·키크기+E+N). 외부 파일을 참조하지 않으며, 큰 DB에서는 입력을 독립 청크로 나눈다. 높은 메모리 비용과 즉시 streaming 불가가 주요 단점이다.

**정보이론적 이유.** 노드v에서 edge별 count가 n_vi이고 총 n_v라면, count가 전달된 뒤 가능한 출발 순서열 수는 `n_v! / Π_i n_vi!`이다. 그 로그 길이로 출발 순서를 열거 부호화할 수 있다. 하나의 수만 반복 출발했다면 순서열 비용은 0 이지만, **그 수의 label·degree·count·topology 전달 비용은 남는다.** 이 부분을 빼고 ‘반복이면 0 bit’라고 계산하면 틀린다.

count가 주어졌을 때 남은 count에 비례해 산술 부호화하는 것과 같은 순서열 모형을 만들 수도 있다. count 전달 비용과 부분집합 비용까지 모두 포함해야 한다. 이 방법이 잘 보정된 online Dirichlet 모델보다 반드시 낫지는 않다.

**악화 조건.** 대부분 상태가 한 번만 나타나는 중후반, 짧은 배치, 높은 degree 설명 비용, 긴 graph record. 유일 경로의 연속 노드는 path로 합치고 일반 RAW 블록으로 escape하는 옵션을 비교하되 해당 플래그도 포함한다. 오프닝 편중 이득을 전체 인간 기보 이득으로 확대 해석하지 않는다.

**C++20 최소 검증.** 외부 학습 없이 현재 23 게임·반복게임·새로운 대규모 배치에서 topology bytes, counts bytes, queue bytes, framing bytes를 따로 측정한다. 처음에는 상태별 큐의 이상적 열거 비용만 분석해보되, 그것은 **이 포맷의 낙관적 부품 비용**이지 전체 코덱의 하한이나 달성률이 아니다. 그 다음 실제 topology 전달을 붙인다. 작은 청크에서는 count가 coder의 total 상한을 넘지 않도록 제한하거나 큰 count용 명확한 정수 부호를 사용한다.

**기술 분류.** 유한상태원·문맥 그룹화·열거 부호화는 알려져 있다. BWT도 가역적 재배열로 문맥의 반복을 모으는 대표적 선행 기술이지만, 본 그래프-출발열 포맷을 BWT와 동일하다고 주장하지 않는다.[S9] DMG의 정확 상태 사전과 공유하는 재등장 정보가 크므로, 정보상의 새 이익은 주로 배치 모형화·순서열 재배열·구조 비용의 절약에서 나와야 한다.

**기각.** topology와 게임 길이·순서를 포함하면 online exact/phrase보다 못하거나, 중복을 제거한 보통 크기의 배치에서 이득이 사라지면 범용 우선순위를 낮춘다. 다만 중복·대형 개국 DB 전용 모드로는 별도 평가한다.

## 13. 안 8: 손실 없는 수순 정규화—동일한 전이의 동치류와 순서 잔차 ★

**발상·차이.** 같은 오프닝 구조를 다른 순서로 만드는 게임을 공통 대표 수순으로 바꾸고, 원래 순서만 따로 기록한다. 개별 위치·이동을 정규화하는 현재 사전과 달리 **여러 반수의 순서를 바꿔** 공통화를 시도한다. 순서 정보는 절대로 버리지 않는다.

**압축·복원.** 길이 4 또는 6 의 고정 창에서 백의 UCI move multiset와 흑의 UCI move multiset를 각각 순열화한다. 시작 상태에서 모든 후보 수순을 엄격히 적용하고, 완전한 최종 착수 상태가 같으며 길이가 같은 경우만 같은 class로 묶는다. 중복 UCI move가 있으면 동일 순열을 중복 제거한다. class의 lexicographic 최소 legal sequence를 대표로 정하고, 실제 수순의 class 내 번호를 저장한다.

6 반수에서는 각 쪽 3 수이므로 최대 `3!·3!=36`개의 순서만 검증한다. 8 반수에서는 최대 576 개다. 이것은 전체 체스 게임 트리 열거가 아니다. decoder는 먼저 대표 수순을 풀고, 그 대표의 양측 move multiset와 같은 최종 상태를 이용해 동일 class를 다시 열거한 뒤 ordinal을 풀어 원래 수순으로 돌린다.

대표 수순의 모델은 정규화된 chunk끼리 학습하도록 분리한다. 실제 기보를 위한 통계·plan state는 ordinal 복원 후 원래 수순을 재생해 갱신한다. 첫 프로토타입은 chunk 내 모형을 고정하면 이 이중 갱신을 단순화할 수 있다. RAW/CANON mode의 선택 비용도 지불한다.

**필요 상태·비용.** O((k/2)!²·k·착수검증), 작은 창의 보드 사본과 sequence 후보. 모든 후보는 castling, en passant, promotion, check 중간 상태를 포함해 검증한다. 공식 종료 규칙까지 처리한다면 그 규칙의 이력을 포함해 equivalence를 더 엄격히 정의하거나, 종료 해석 없이 UCI 착수 기록에 한정한다.

**정보이론적 이유.** 변환 자체는 정보량을 줄이지 않는다. 공통 대표의 분포를 더 쉽게 학습하거나 COPY하는 이득이 `순서 ordinal+mode` 비용을 초과해야 한다. class 크기가C라면 균등 ordinal 비용은 대략 log2 C이고, 빈도 기반 순서 분포로 더 줄일 수도 있다. 최종 보드만 보내면 충분하다는 주장은 잘못이다. 서로 다른 경로가 정확히 복원돼야 한다.

**악화 조건.** 대다수 class가 singleton, 드문 대표, 비정상적인 lexicographic 대표, 순서 비용이 큰 개국, 실제 순서의 강한 규칙을 정규화가 지워버리는 경우. class 확률을 전체 게임 트리에서 합산해야만 동작하는 설계는 채택하지 않는다. 대표를 보통의 legal sequence로 직접 부호화하는 유효하지만 보수적인 구현부터 시작한다.

**C++20 최소 검증.** k=4/6 에서 class 크기, 대표의 실제 중복 증가량, ordinal 실측 비용을 먼저 조사한다. 같은 baseline으로 raw sequence와 canonical sequence를 비교하고, 그 다음에만 phrase 사전을 결합한다. 독립 평가에서 representative dictionary를 무료로 미리 제공하면 안 된다.

**기술 분류.** 교환 가능한 사건의 partial-order/trace 표현과 순열 열거는 기존 개념. 제한된 체스 수순의 정규화·참조·순서잔차 결합은 독창적 연구 가설에 가까우나 선행기술 완전조사나 최초성 증명을 한 것은 아니다.

**기각.** 대표 중복 증가가 드물거나, canonical 비용 감소보다 ordinal 비용이 지속적으로 크면 빠르게 중단한다. 실용성과 범용성에서 우선순위가 가장 낮은 축이다.

## 14. 안 9: 현재 배치에서 배운 작은 모델을 전송하는 두 부분 부호

**발상·차이.** online 모델은 초기 배치에서 학습비를 낸다. 배치 전체를 먼저 보고 작은 모형을 맞춘 다음, 모형을 압축 데이터 안에 넣어 처음부터 쓴다. 미래 정보는 공짜가 아니라 **모델 전달 비트**를 내고 사용한다. 별도 pretrained 파일이나 외부 모델은 없다.

**압축·복원.** 제한된 관계·gap 특징의 정수 계수, 작은 문맥 확률표, 또는 소수의 script별 prior만 현재 archive에서 추정한다. 최소화 목적은 `L(model)+L(data|model)`이다. 계수는 baseline 대비 차이·희소 index·정수 Rice 등의 작은 부호로 보낸다. decoder는 모델을 먼저 읽은 뒤 동일 legal 후보와 산술 부호기로 복원한다. 이후 online 잔차 적응을 허용할지 별도 mode로 명시한다.

배치 일부로 훈련한 뒤 나머지의 계수를 몰래 공통 라이브러리에 포함시키는 방식은 금지한다. 개발 데이터로 고정하는 것은 특징 추출 알고리즘과 학습 규칙뿐이며, 개발에서 학습된 가중치를 평가 코덱 초기값으로 배포하지 않는다.

**필요 상태·비용.** 입력 버퍼 또는 2 회 순회, 제한된 D차원 모델의 fitting, sparse model serializer. 인코더만 수회 학습할 수 있고 디코더는 1 회 예측으로 충분하다. 원시 float 계수 배열 대신 정수화된 실제 모델을 기준으로 최종 최적화한다.

**정보이론적 이유.** online cold start 비용보다 작은 설명 길이의 모형으로 전체 배치의 분포를 설명할 수 있으면 이긴다. 미래를 썼다는 이유로 entropy를 깨는 것은 아니다. 총 코드는 모델과 데이터의 joint description이다.

**악화 조건.** 작은 파일, 복잡한 모형, 혼합된 자료, 계수의 정밀도 비용. 64 개 int16 계수만 단순 저장해도 1,024 bit이며, 1,718 반수에서는 헤더 없이도 약 0.596 bit/반수다. 이 예만으로도 작은 표본에서 무거운 모형 전달이 불리함을 알 수 있다. sparse/delta 부호의 실제 비용을 재야 한다.

**C++20 최소 검증.** D=8/16/32 같은 작은 모델부터 양자화 정밀도를 바꿔 실제 `model_bytes+data_bytes` 곡선을 만든다. archive 크기를 게임 1/16/256/4096 개 등으로 바꿔 손익분기점을 찾는다. 모든 모델 후보를 시도해 가장 작은 것을 고를 때도 최종 모형 ID·모형 bytes를 포함한다.

**기술 분류.** two-part MDL와 static/semi-static 모형 전송은 알려진 기술. archive 내부만으로 학습한 작은 관계 모형과 online residual을 결합하는 것이 DMG용 새 조합이다.

**기각.** model cost를 빼야만 이기거나, 충분히 큰 보통 배치에서도 online 대조를 이기지 못하면 그 모형 계열을 기각한다.

## 15. 최상위 3 개와 우선순위의 이유

1. **안 1—관계 기반 조건부 선택 학습.** 일반화 대상과 학습 목적을 함께 바꾼다. 정확한 상태 재등장 없이도 작동하며, 기존 C++ 후보·산술 코더를 재사용할 수 있다. 새 정보의 가치와 학습 방식의 가치를 분리해 검증하기 쉽다. 가장 먼저 구현할 연구다.
2. **안 2—제한된 반사실 탐색.** 현재 없는 ‘상대가 응수했을 때의 결과’라는 강한 정보원을 만든다. 비용을 크게 쓰지 않고도 static feature와 다른 정보를 얻을 가능성이 있다. 인간 선택에 맞춘 확률교정과 tail 보존이 필수다.
3. **안 6—가변 길이 생성 프로그램.** 부호화 단위를 바꾸는 대안 중 구현·반증이 비교적 쉽다. 단일 게임의 전술 수순과 대량 게임의 phrase 재사용을 모두 시험할 수 있다. 다만 모드와 RAW 세금이 손익을 지배할 수 있다.

이 순위는 측정된 미래 bit/반수 순위가 아니다. **일반 인간 기보에서의 이익 가능성, 개발비, 검증 가능성**에 대한 연구 판단이다. 입력이 수백만 개 게임의 개국 DB로 확정되면 안 7 을 3 위권으로 올린다.

## 16. 제안 아키텍처: DMG 연구용 R1

처음부터 9 개를 모두 붙이지 않는다. R1 의 core는 완전 합법 후보, 관계 기반 online 조건부 선택, 선택적인 finite-search 정보, 안전한 mixture다. 안 6 은 같은 core를 RAW로 쓰는 별도 가변길이 mode로 추가한다. 안 7/8/9 는 서로 다른 batch 표현 실험이며, 처음 core에 넣지 않는다.

### 입력·출력과 상태

- 입력: 게임 순서를 보존한 `vector<vector<Move>>`, 표준 초기 상태, 정확한 UCI 착수 순서. 공백·줄바꿈·UCI 대소문자 같은 원본 텍스트 형식까지 복원하는 목표는 포함하지 않는다.
- 출력: magic/version, 모델·산술 규격 ID, 게임 수와 각 길이, 청크 경계·reset 정책, payload, byte padding, checksum. 임의 초기FEN·태그·결과는 현재 범위 밖이며 추가하면 별도로 비용을 센다.
- `Position`: board, bitboards, side, castling, en-passant.
- `History`: 이전 원시수, 백흑별 이전 착수와 필요시 동작 이력, repetition 검증용 상태. 공식 종료를 강제할지는 버전 규격으로 고정한다.
- `RelationalWeights`: 고정용량 정수 가중치와 정규화 상태.
- `SearchWorkspace`: 고정 node budget, TT, 안정된 탐색순서.
- `Exact/PatternStore`: 제한된 사전, 결정론적 eviction. 원래 v7 을 비교 expert로 남긴다.
- `ExpertState`: archive-level static Bayes prior, 작은 switch mixture. 강제 게임 reset과 지속 정책을 format에 지정한다.
- `GrammarStore`: macro mode에서만 사용하는 bounded script·과거 수순 창.

### core의 의사코드

```text
encode_archive(games, spec):
    header = make_header(spec, game_lengths, chunk_reset_policy)
    state = cold_state(spec)        # 외부 가중치 없음
    coder = ArithmeticEncoder(spec)

    for each chunk in fixed_input_order:
        reset_exactly_as_specified(state)
        for game in chunk:
            P = standard_position()
            H = empty_game_history()
            reset_only_game_local_state(state)
            for y in game:
                legal = sorted_all_legal_moves(P)
                assert y in legal
                frame = predict(P, H, legal, state, spec)
                coder.encode(index(y, legal), frame.quantized_cdf)
                observe(P, H, legal, y, frame, state)
                P = apply(P, y)
                H = append(H, y)
    return header + coder.finish() + padding_and_checksum

decode_archive(bytes):
    header = parse_and_validate_header(bytes)
    state = cold_state(header.spec)
    coder = ArithmeticDecoder(bytes.payload)

    for each declared chunk and game:
        perform_the_same_resets(state)
        P = standard_position()
        H = empty_game_history()
        for t in 0 .. declared_game_length-1:
            legal = sorted_all_legal_moves(P)
            frame = predict(P, H, legal, state, header.spec)
            y = legal[coder.decode(frame.quantized_cdf)]
            observe(P, H, legal, y, frame, state)
            P = apply(P, y)
            H = append(H, y)
            output y
    validate_lengths_end_state_checksum_and_payload_end()

predict(P, H, legal, state, spec):
    b = normalized_legal_baseline(P, H, legal)
    phi = relational_delta_features(P, H, legal)
    q_rel_quantized = quantize(fixed_point_softmax(log_b + dot(state.theta, phi)))
    q_old = old_opportunity_expert_on_legal_set(P, H, legal, state)
    q_uniform = uniform_over(legal)
    experts = [q_rel_quantized, q_old, q_uniform]
    if spec.search_enabled:
        scores = deterministic_complete_root_search(P, legal, spec.budget)
        experts += [online_calibrated_search_distribution(scores, state)]
    q = specified_router(experts, P, H, state)
    cdf = deterministic_quantize(q, positive_mass_for_every_legal_move)
    return all_preupdate_predictions_features_and_cdf  # q_rel_quantized 포함

observe(P, H, legal, y, frame, state):
    # 반드시 부호화·복원에 사용한 갱신 전 frame을 사용
    update_relational_parameters_from_selected_minus_expected(frame.q_rel_quantized, y)
    update_expert_evidence_from_preupdate_predictions(frame, y)
    update_dictionaries_and_calibration(P, H, legal, y, frame)
    perform_deterministic_eviction_if_needed()
```

core는 모든 합법수에 양의 질량을 남긴다. 합법수가 하나라면 부호기 구간 갱신을 생략할 수 있지만, 이력과 학습 갱신은 같은 순서로 실행한다. 복수 합법수 중 탐색의 최선수만 확률 1 로 두면 안 된다.

### macro mode의 추가

```text
for each game/block with known length:
    # 후보와 비용은 원시 prefix에만 의존하고 선택한 parse에는 의존하지 않음
    for t from 0 to length-1:

```

decoder는 각 token을 엄격히 전개하고, 실제로 출력된 모든 반수에 대해 observe와 이력 갱신을 한다. script 정의·정렬·참조 창을 바꾸면 format version도 변경한다.

### escape의 정확한 형태

복원 측이 미리 아는 후보 부분집합 A가 유효하다면, `P(ESC)=e`, A 안에는 `(1−e)q_A`, A 밖에는 `e·q_base(m)/(1−Σ_{a∈A}q_base(a))`를 줄 수 있다. escape 뒤에 A를 다시 포함한 전체 baseline을 쓸 필요는 없다. 집합과 제외 규칙은 양쪽이 미리 계산할 수 있어야 한다. 이는 실패 비용을 없애는 것이 아니라 이미 부정된 후보를 두 번 세지 않는 방법이다. 단순한 고정 성공 접두부로 돌아가자는 제안은 아니다. A가 전체 합법수 집합이면 escape를 제거하고, A가 비어 있으면 전체 baseline만 쓴다.

## 17. 실험 설계와 순서

### 17.1 표본과 학습 범위

기존 23 게임과 이전 4 게임은 모두 개발용이다. 첨부 파일명에서 23 게임 중 20 개는 유명한 역사적·상위권 대국으로 보이며 나머지 3 개가 저기력 자료다. 이런 구성은 전술적 명장면·오래된 오프닝·긴 단일 게임에 편향될 수 있다. 따라서 ‘일반 인간 기보’의 대표 집합으로 간주하지 않는다.

새 자료는 예를 들어 개발 1 만 게임, 검증 1 만 게임, 최종 독립 5 만 게임 규모로 계획하되, 이는 예산에 맞출 실험 설계 예시다. 먼저 수천 게임의 넓은 표본으로 잘못된 가설을 탈락시킬 수 있다. 기력·시간제어·연대·게임길이를 층화한다. 표준 체스만 포함하고 변형·비표준 시작FEN·불법 UCI는 제외 사유와 수를 기록한다. 실제 수집·다운로드는 이번 보고서에서 수행하지 않았다.

정확한 게임 중복과 긴 거의 동일 수순이 개발·최종 집합을 넘지 않도록 그룹 분리한다. 오프닝 분포가 비슷한 평가와, 다른 오프닝군에서의 일반화 평가를 별도로 만든다. 모든 오프닝 재등장을 무조건 제거하면 실제 batch 사용처를 훼손하므로, ‘게임 중복 제거’와 ‘공유 개국 위치 제거’를 혼동하지 않는다.

개발에서 학습한 가중치를 평가 코덱에 넘기지 않는다. 각 독립 archive는 규정된 cold state에서 시작한다. 평가 archive 내부에서 이미 복원한 게임으로 배우는 것은 허용된 online 압축이며, 외부 사전학습과 구분해 기록한다. 안 9 의 배치 전체 학습은 모델이 파일에 들어가는 포맷 자체의 기능이므로 허용하되 그 bytes를 포함한다.

### 17.2 분리해야 할 자료와 조건

| 축 | 조건 | 확인할 점 |
|---|---|---|
| 인간 자료 | 기력·시간제어별 / 혼합 | 강한 선수에서만 이기는지 |
| 무작위 | 매번 전체 합법수 균등 선택, 여러 고정 seed | 인간 편향 손실과 uniform 복귀 비용 |
| 반복 | 동일게임·부분수순 반복·비율별 중복 | 사전의 정당한 재사용 이익 |
| 단일 게임 | 매게임 완전 cold start | batch 학습에만 의존하는지 |
| 배치 | 16/256/4096 게임 등 여러 크기 | 헤더·모델·사전 비용의 분기점 |
| 순서 | 원래 순서 및 여러 고정 permutation | online 학습의 순서 민감도 |
| 국면 | 오프닝/중반/엔드게임 | 개선 위치와 실패 위치 |

국면 분할은 미리 고정한다. 예를 들어 v7 material_phase≤8 이면 엔드게임, 나머지 중 0～19 반수는 오프닝, 그 외는 중반으로 하면 서로 겹치지 않는다. 다른 정의를 쓰면 결과를 섞지 않는다. 국면 분석용 절편은 원게임의 누적 상태로 점수를 집계하는 분석과, 별도FEN부터 압축하는 실험을 구분한다. 후자는FEN 전달 비용이 필요하다.

### 17.3 반드시 저장할 측정값

1. 양자화 전 분석용 `Σ−log2q`, 실제 정수CDF의 `Σ−log2(freq/total)`, payload bit 수, payload byte padding.
2. model/table/topology/token-parameter bytes, 게임 길이·청크·index·checksum·version bytes, 총 파일bytes.
3. `payload_bits/N`와 `8×total_bytes/N`. 모델 전송을 숨기지 않도록 ‘착수열만의 길이’와 ‘모델비 포함 압축부 길이’를 나란히 쓴다.
4. 압축·복원 시간, 고정된 머신과 thread 수, peak RSS, 기물·후보·탐색노드당 비용. 명시적으로 정보모형 없는 속도 비교와 실제 코덱을 구분한다.
5. 게임별 평균·중앙값·상위 손실, 전체반수 가중평균, 국면별 길이. 한두 개 긴 게임의 개선이 전체를 지배하는지 확인한다.
6. 낮은 확률 꼬리, 예컨대실제수의 확률<1/64 또는<1/256 비율과 그들이 낸 총bit. 최상위 정확도와 함께 보되 압축 판단은 로그손실로 한다.
7. byte 동일 재인코딩, C++/Rust·x86/ARM 간 golden stream, 매반수 상태·CDF hash의 첫 불일치 위치.

### 17.5 사전 등록할 채택·기각 기준

- 확정 기준은 ‘전체 평균<3.9/3.5’뿐 아니라 그 목표가 **payload인지 total인지**까지 포함한다.
- 연구 투자 기준으로, 예컨대검증에서 0.05 bit/반수 이상의 개선과 독립archive 간 일관성을 요구할 수 있다. 이는 예상 성능이 아닌 **사전에 선택할 최소 실용 개선량**이다. 최종 판정은 충분히 정밀한 신뢰구간과 시간·메모리 예산을 함께 사용한다.
- 검증에서 해당 최소량을 배제할 만큼 정밀하게 이익이 작거나 음수이면, 해당 설계·용량·예산의 가설을 기각한다. 표본이 작아 0 근처라면 결론 유보이지 원리 전체의 반증은 아니다.
- 오프닝·반복 자료에서만 이기면 그 용도에 한정한다. 인간 일반화를 주장하려면 중복 없는 중반·엔드게임과 혼합 기력에서도 결과를 따로 제시한다.
- 반복 실험의 2.159 는 일반 인간 기보의 도달 근거로 사용하지 않는다. 이번 합법수 실험의 4.0943 도 독립평가 성능이나 새 안들의 예상 성능으로 쓰지 않는다.

## 18. 구현 위험과 형식 규격

**정수 범위.** 현재 coder는 total<32768 을 요구한다. 양의 최소 빈도 1 을 유지하고 후보수보다 작은 total은 허용하지 않는다. raw 합·빈도 곱·posterior 곱의 최대값을 식으로 증명하고 곱셈 전에 타입을 승격한다. uint64 가 충분하다고 추정하지 않는다. 필요하면 128bit 중간곱이나 검증된 mul-div를 쓴다. MSVC·Rust에서도 같은 산술 의미를 규격화한다. signed overflow, 과도한 shift, 빈 bitboard의 bit scan을 피한다.

**부동소수점 결정론.** exp/log는 모델 설명식이다. 배포 decoder는 고정점 LUT와 고정된 반올림·포화·분모·잔여 질량 배분을 사용한다. LUT는 고정 상수로 생성하며 외부 학습 가중치로 대체하지 않는다. fast-math·FMA·플랫폼 libm에 따라 달라지는 CDF를 피한다.

**CDF 양자화.** 총빈도와 양의 최소빈도를 확보한 뒤 잔여 빈도를 floor 및 최대 나머지 배분 등으로 결정론적으로 나눈다. 동점은 고정 후보순서로 처리한다. 바닥확률은 편의가 아니라 실제 모형의 평활화이므로 효과를 따로 측정한다.

**동기화.** 매 수에서 예측→encode/decode→모델갱신→착수→이력갱신 순서를 고정한다. 이전 수 특징의 갱신 전후가 섞이면 안 된다. unordered_map의 순회순서·주소·표준 라이브러리별 hash를 CDF나 축출 결정에 쓰지 않는다. 고정 hash와 명시 index 또는 완전키를 사용한다. 통계 감쇠·reset·캐시 축출도 같은 순서로 한다.

**상태 일치와 hash.** 특징 가중치표의 hash 충돌은 양쪽이 동일하게 처리하면 일반화 품질 문제다. 반면 그래프 노드나 COPY 전제조건을 같은 상태로 합칠 때 hash만 믿으면 안 된다. 완전키 확인이 필요하다.

**특수 착수.** 승격 4 종·잡는 승격·앙파상의 별도 제거칸과 왕 노출·캐슬링 경유칸 공격과 권리 소멸·포획된 rook의 권리·핀·이중체크를 엄격히 처리한다. trial/unmake는 모든 권리·bitboard·기물ID를 복원한다. 현재의 배열 256 을 모든 의사합법 후보의 증명된 상한으로 간주하지 말고, 상한 검증이나 확장 가능한 저장을 쓴다.

**청크와 접근.** 독립 복원을 원하면 청크의 모든 학습 상태를 reset하거나 checkpoint로 전달해야 한다. 공유 사전이 남았는데 payload만 나누면 독립 청크가 아니다. 청크 크기는 압축률과 접근 비용의 절충이며 checkpoint·index도 총길이에 포함한다.

**특이 입력.** 0 게임·빈게임·합법수 1 개·긴 게임·반복 사이클의 지원 범위를 명시한다. 게임 길이를 mate로만 추론할 수 없다. 인간 대국은 기권·합의 등으로 임의 시점에 끝난다. 손상 파일의 길이·참조·분모·토큰 전개를 검증하고 무한루프를 제한한다.

**검증.** 새 모형을 구현할 때 정상 왕복만 확인하지 않는다. 특수수 golden case, 여러 플랫폼의 정확한 bytes·CDF 일치, reset 경계, 메모리 상한, 정수 범위, ASan/UBSan을 확인한다. 이번 실험은 원본 DMG7 테스트와 23 게임 변경판 왕복까지다. 새 9 안의 정식 구현 검증은 아직 수행하지 않았다.

## 19. 구체적인 첫 작업

지금 권할 작업은 **완전 합법 후보를 새 대조군으로 고정하고, 관계 특징 20～40 개를 실제 후보 경쟁의 온라인 로그손실로 학습하는 작은 모델을 만드는 것**이다. 기존 expert를 그대로 둔 경로 prior 실험도 병행하면 모형 개선과 혼합 개선을 구별할 수 있다.

그다음 제한 탐색이 추가 정보를 주는지 확인하고, 보완적일 때만 결합한다. 여러 반수 프로그램은 별도 연구 가지에서 전체 비용을 계산한다. 대형 DB의 구조 변환인 안 7 과 순서 정규화인 안 8 은 유리한 입력 분포가 다르므로 처음부터 core의 필수 기능으로 넣지 않는다.

3.9 에 필요한 개선량 약 0.224 bit/반수, 3.5 의 약 0.624 bit/반수는 새로 이용해야 할 정보의 크기다. 부호기 이름을 바꿔 이 목표에 도달한다고 예측할 근거는 없다. **서로 다른 위치에서 같은 선택 구조를 배우고, 상대 응답과 지속되는 의도를 활용하며, 반복 수순의 전체 설명길이를 줄이는 것**이 실질적인 연구 대상이다.

진단에서는 매 수의 v7_step() 출력 CDF에 대해 `-log2(selected_weight/total)`을 합했다. 각 후보를 복사한 판에서 apply_checked()해 합법 빈도합을 구하고, `-log2(legal_weight/total)`을 합하면 50.727341 bit가 된다. 이 진단의 학습 경로는 원본 그대로 유지했다.

실제 합법화 실험은 별도 소스 복사본에서 아래 early return 두 줄을 제거하고 다른 로직은 유지했다.

```cpp
// remove_illegal_during_check()에서 제거한 조건:
int sq = p.king_square(p.side);
if (sq < 0 || !p.square_attacked(sq, p.side ^ 1)) return;
```

v7 은 이 함수를 호출하는 mode를 쓰므로 모든 후보가 검증된다. 이후 v7_encode/v7_decode에 23 게임을 넣어 네 모드의 왕복과 표의 길이를 확인했다. 배포용으로는 함수명·format version을 바꾸고 독립 자료·특수수·플랫폼 검증을 추가해야 한다.
